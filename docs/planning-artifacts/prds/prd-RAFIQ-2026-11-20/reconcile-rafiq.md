# RAFIQ input reconciliation

Compared the draft PRD with the original `RAFIQ.md` feature brief and the interview decisions recorded in `.memlog.md`. The follow-up decisions control when they change the brief.

## Findings

1. **Live monitoring visibility.** Feature 1 specifies that the application displays a live feed while analyzing behavior (`RAFIQ.md:87`), and Feature 7 says it displays the current driver state (`RAFIQ.md:123`). FR-04 explicitly offers a stationary camera preview and shows the session state. FR-05 and FR-07 cover detection and warnings, but do not state what RAFIQ displays for observed normal behavior and other current driver states during monitoring. The interview log confirms on-device observation and the supervised moving-use restriction. It does not explicitly defer live visibility. Confirm which live information the driver or supervisor should see during stationary and moving sessions, and give any deferred item an explicit disposition.
2. **Personal data export.** The brief lists data export separately from reporting (`RAFIQ.md:48`), although it provides no format or fields for a personal data export. FR-19 implements PDF and Word report export. The interview log confirms those formats without recording a decision about exporting the driver's underlying session observations. Identify this as an open or deferred feature unless the user confirms a launch data export requirement.
3. **Report content and types.** The brief names individual driver safety, statistical research, and detection evaluation reports (`RAFIQ.md:301` and `RAFIQ.md:303`). FR-19 captures review, PDF/Word, figures, evidence, and insufficient-data behavior. OQ-8 explicitly leaves benchmark reports open. Individual and experiment report coverage is implicit, so identify what the MVP can report from and which report types require a later decision. Maintain the interview decision that report generation is subject to the driver's authorization.
4. **Interactive chart coverage.** Feature 20 describes interactive charts, visual indicators, summaries, and comparisons (`RAFIQ.md:209`). FR-14 confirms an interactive timeline, comparisons and descriptive views. It does not establish whether the descriptive dashboard itself offers interactive visualizations outside the timeline. Confirm whether the timeline is the only required interactive visualization or record an acceptance check for the minimum dashboard chart interactions.

## Reconciled decisions

- The brief's educational demonstration and labeled-data basis carries into controlled testing, the academic deadline, and repeatable release evidence. The user's supervised SaaS launch intent governs the first release. Pilot and public enrollment order remain open.
- On-device camera monitoring, offline continuation, a built-in camera and one named desktop browser supersede the brief's broad connected-webcam description. Exact device support and procedures remain open.
- The pilot's validated high-risk list, stationary driver interactions, registered verified email contacts, ordered attempts, cancellation, recovery and retry rules define the emergency capability. Public live delivery remains separately gated by pilot evidence.
- The driver is the sole signed-in role. Private personal analytics and service-wide retention supersede tentative workspace selections. No researcher or administrator access to driver records is included. Experiment Studio and its participant or dataset protocols remain separate decisions.
- The scope table accounts for all 34 source features. Live alert explanation, timeline, simulation, experiments, reporting and MCP move into the first release. Calibration, risk score and longitudinal behavior analysis are deferred. Held-out evaluation is release evidence, with driver-facing exposure open. Fixed live policies and read/report MCP behavior supersede the brief's broader configurable live thresholds and authorized MCP settings mutations.
- The draft preserves qualitative priorities of timely, understandable warnings, meaningful reproducible analysis, and privacy. The exact thresholds, sample protocol, cohort and program rollout remain approval points. The email acceptance interpretation is marked for approval.
