# D10 Clips — Pen.dev handoff

The driver uses Clips while stationary to find evidence from a completed session, see whether the recording is available and when it expires, then replay it or delete it and continue reviewing the incident. On 25 November 2026, the user approved **A · Structured evidence list** and **standard controls with a brief Back highlight** (D10-C01, D10-C04, D10-C06, D10-C08). [D10 requirements](../../SCREENS.md#d10-clips) · [Layout and component research](D10-COMPONENT-RESEARCH.md)

## Frame and hierarchy

1. **Private shell.** Reuse D06’s navigation layout with **Clips** selected and the existing **Start session** action. Put **Clips** in the main heading. Use the D06 desktop shell at 1440 px and its stacked navigation convention at narrow widths.
2. **Search and scope.** Show labeled **Behavior**, **Capture date**, and **Session** controls followed by **Apply**. Start with any eligible behavior, date and session. Put applied selections and **Clear filters** immediately below the controls. Keep changes to the controls distinguishable from the selections already applied to results. Show **Newest captures first** and the local time zone above the results. Filters combine one behavior, one owned session and capture-date bounds. Interpret date selections in the displayed zone and send inclusive start and exclusive next-day bounds in UTC. Typing to find an owned session option is conditional on a complete authorized lookup. The current search contract is structured filters.
3. **Results.** Use a flat aligned list with columns for **Behavior and incident time**, **Source session**, **Clip status and expiry**, and **Actions**. Put the behavior label first, with exact local incident time and date below it. Distinguish incident time from capture time. Keep a combined incident in one entry with all recorded behaviors available. Link the session label to D07 and use **View incident** to resolve the selected D08 occurrence when authorized. Show state with text and a non-color cue. Use **Expires** or **Queue expires** with an exact date and time when known. Show the playable recording duration where useful and label truncation **Available first segment**. Provide **Open clip** for playable media and a visible, keyboard-reachable actions trigger. Keep results text-led and use no media fetch in the library.
4. **Paging and reflow.** Continue with explicit cursor-based controls using D06’s paging pattern. Keep paging errors by the controls and restart pagination when the applied filter scope changes. At 390 px and 320 CSS px, wrap controls and stack row fields in the same reading order with visible field labels. Preserve clip and incident actions through 200% zoom. Use one page scroll.

Reuse the D06 shell, dividers, paging, static skeleton and scoped feedback (`m14mRu`, `AXgTB`, `ltZ40`, `rYjYy`), plus D07 and D08 evidence labels and incident context (`xRhDe`, `S3YUmp`). Match the existing Space Grotesk substitute for Mori, `colors.canvas` (#0e100f), `colors.ink` (#fffce1) and `colors.accent-stone` (#bbbaa6). Use `spacing.sm` (8 px) within status groups, `spacing.md` (16 px) for row padding and control separation, `spacing.xl` (24 px) between major groups, and `rounded.md` (8 px) where existing controls and feedback use it. New RAFIQ visuals are the evidence row and the availability/expiry readout. Reuse the existing focus and destructive-action treatments. ## Interaction and states

| Trigger or state | Treatment |
| --- | --- |
| Initial load | Preserve shell and filters. Show static result-shaped skeletons and announce **Loading clips** once. Hide placeholder shapes from assistive technology. |
| Apply or clear filters | Preserve keyboard focus, identify the applied scope and mark the results busy. If earlier results remain visible during refresh, label their earlier scope. Announce the settled result state once. |
| First use or no retained clips | Use **No clips yet** when first use is known, with a brief explanation and a **Monitoring settings** route when relevant. Use **No clips available** and a **Sessions** route when prior history is unknown. |
| No matches | Show **No clips match these filters** after a successful lookup. Keep applied selections visible with **Clear filters**. |
| Offline, load failure or paging failure | Explain the unavailable scope and keep valid selections. Offer scoped **Retry** when eligible. Label any verified same-device queued entries as local. Keep unknown hosted status distinct from an empty library. |
| Queued, uploading or pending | **Queued** and **Uploading** require reliable device or transfer state. Show measured progress only. Remote `pending` by itself reads **Pending**. Keep playback unavailable until the clip is eligible. |
| Available or truncated | Show expiry, **Open clip**, and the first-segment label when applicable. D11 starts playback on driver request. |
| Unavailable or expired | Show the verified reason for authorized records where supplied. In D08, recording declined, excluded category and failed capture or upload limits are historical context only when the service provides the facts. Independent incident evidence stays available according to its own retention. Use P08’s generic unavailable treatment when a protected destination can no longer be authorized. |
| Return from D11 | Restore the same applied filters, page, scroll and activated row after revalidation. Focus **Open clip** when it survives, then the current row status or nearest surviving row, then the results heading. |
| Delete a clip | Give the menu trigger a name such as **Actions for Phone use at 09:42:18**. Show **View incident** and **Delete clip** as applicable. If deletion is the only action, use a named text button. In the confirmation, identify the behavior and timestamp, focus **Cancel**, and explain loss of replay and linked access, preservation of the independent session and incident, and withdrawal of any dependent hosted report. Show **Deleting…**, then **Clip deleted** only on confirmation. Move focus to the next surviving row or heading. Keep the target visible on a recoverable failure and revalidate an uncertain outcome. A deleted queued clip must be ineligible for retry or publication. |

Queued recordings expire 24 hours from capture. Hosted clips expire seven days from capture. Independent session and incident metadata expire 90 days from session end. At expiry or deletion, access ends immediately and retained copies are purged within 30 days. Link to D22 **Privacy** for the full retention explanation. Keep only current-authority private state in view. Clear it on sign-out, account switch or access loss. D11 owns authenticated replay and media cleanup. ## Motion and accessibility

- **0 ms** — After a successful Back restoration, display the restored results, scroll position and focus immediately. Show the row’s static selected treatment and begin a subtle emphasis on the existing accent. If the row has vanished, use the focus fallback directly.
- **150–180 ms** — Settle accent opacity at its resting state. Keep geometry, focus ring and content fixed. A CSS opacity transition is sufficient. Reduced motion displays the resting state immediately. Keep opening menus, applied filters, loading, empty states, state changes and deletion immediate.
- Label fields, navigation landmarks, result headings and clip actions. Retain table header associations where shown and explicit field labels in stacked rows. Test Tab order, menu arrows and Escape, menu-to-dialog focus, cancel, deletion focus fallback and once-only status announcements. Keep the visual highlight independent of keyboard focus. Confirm a bounded authorized way to supply behavior, actual incident time, readable session reference and supported historical reasons.
