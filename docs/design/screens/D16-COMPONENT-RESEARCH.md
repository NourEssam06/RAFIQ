# D16 Benchmark — design proposal and component research

**For review.** The selected priority is to compare detection quality across behaviors immediately after the evaluation scope and sample. The layout and motion choices below are proposals for approval.

## Job and evidence

D16 is an **Operate** dashboard for an eligible, signed-in driver reviewing RAFIQ outside an active monitoring session. Open it from **Analysis → Benchmark** or an approved reference in **D18 Report review and export**. Keep **Analysis** current in the driver shell. Offer **Back to report** on a verified report entry and **Back to Analysis** otherwise. A report reference must preserve the identity of its approved evidence before D16 can claim to show the same release. [D16 requirements](../../SCREENS.md#d16-benchmark) · [Experience](../../EXPERIENCE.md#what-if-experiment-studio-and-benchmark) · [API](../../API.md)

The driver should be able to identify which released behavior system was evaluated, compare how often it detected or missed each behavior, and judge those figures against observation coverage, sample size, warning performance, and limitations. The evidence is approved aggregate output from a consented, driver-disjoint, controlled stationary or simulator holdout. Routine private sessions stay outside it. The protocol requires at least five held-out drivers, twenty independently staged positive episodes per behavior, and five monitored hours. Treat these as protocol minimums. Show actual released sample figures only when supplied. Keep evaluation inputs, participant drill-down, running evaluations, policy controls, and dedicated benchmark export outside this driver view. [PRD FR-18 and protocol](../../PRD.md#83-benchmark-and-behavior-policy) · [TRD analytics](../../TRD.md#5-statistical-analysis-and-reports) · [Architecture](../../ARCHITECTURE.md#j5-simulate-run-a-study-and-interpret-the-benchmark)

## Layout options

| Option | Composition and interaction | Trade-off |
|---|---|---|
| **A · Comparison with a detail panel — recommended** | Heading and release scope first. At wide widths, horizontal behavior comparison on the left and the selected behavior’s confusion matrix and coverage on the right. Below them, a full-width row for overall coverage, false warnings per monitored hour, and warning delay, then methods and the exact-value data view. | Keeps the comparison and its underlying counts visible together. The selected detail needs a distinct heading and enough width for full labels. Reuses D07’s breakdown/readout vocabulary and D09’s measure selector and horizontal bars. |
| **B · Comparison with details below** | Same header and scope. Full-width comparison with compact per-class coverage alongside each row. An explicit **View counts** action in a row opens that behavior’s matrix directly below it. Overall coverage and warning performance appear in the next section. | Leaves more room for long behavior labels and a full-width chart. An expanded row pushes subsequent behaviors down and makes quick repeated comparisons slower. Follows D07’s in-page evidence pattern. |

For A at roughly 1440 CSS px, give the comparison around two thirds of the body and the detail around one third. When labels, values and a readable matrix cannot fit, stack in this order: scope, comparison, selected detail, warning and overall coverage summary, then methods and exact data. Stack summary metrics into rows on narrow layouts. Test at 1024 px, 390 px, and 320 CSS px equivalent at 400% zoom. Allow the exact-value table to scroll within its own labeled region where necessary. Keep the page itself free of horizontal overflow and allow long IDs and labels to wrap. ### A · Proposed reading order

1. **Benchmark**. Place **Controlled held-out evaluation** with the scope summary, monitored hours, and actual authorized sample counts. Surface the benchmark release identifier when supplied. Keep dataset, annotation guide, behavior catalog, model, policy and scoring versions available together in **Evaluation details**. Identify the actual stationary or simulator scope when the release supplies it. Show the published limitations in the methods section, and place any interpretation-changing limitation beside the affected result.
2. **Detection by behavior**. Default to **Precision and recall** as a labeled pair of horizontal bars per behavior with a shared 0–100% scale. Include **F1 score** and **Accuracy** as alternate measures with the same scale. Use stable catalog order across measure changes, exact value labels, and a per-behavior coverage value in each row. Use distinct labels or mark shapes in addition to color. Choose the first behavior with published counts by default. An explicit behavior control or direct bar activation selects the behavior and updates its detail in place. Provide the same action in the data view. Preserve selection across measure changes, including when its metric is unavailable.
3. **[Behavior] · Confusion counts**. Show one 2 × 2 matrix for that behavior. Use **Reference label** on rows and **RAFIQ prediction** on columns, with **Present** and **Absent** on both axes. Present/Present is correctly detected (TP), Present/Absent is missed (FN), Absent/Present is detected when absent (FP), and Absent/Absent is correctly absent (TN). Show all four counts in text and give the selected cell a visible outline. Selecting a cell by click, tap, or Enter/Space updates a compact, persistent readout of the label, exact count, and meaning. Keep the selected behavior, scored frames, unusable frames, and coverage visible near the matrix. Each behavior has its own binary judgment because behaviors may overlap.
4. **Coverage and warnings**. Show overall coverage, the false-warning rate, and warning delay as adjacent metrics with denominators or sample counts. Give the 95th percentile (p95) the primary delay position. Show median (p50) and maximum only when approved and returned. Place the warning-delay reference point and unit alongside the metric. Use labeled values for returned summaries. A distribution or a release-gate verdict requires corresponding approved evidence.
5. **Metric definitions and methods** and **View data**. Provide a keyboard-accessible disclosure for formulas, sample/exposure scope, freezing and exclusion rules, score versions and released limitations. Provide a semantic data table with one row per evaluated behavior, precision, recall, F1, accuracy, class coverage, TP/FP/FN/TN, unusable counts and relevant denominators or references to grouped headers. Short definition tooltips may duplicate plain-language explanations. Any essential condition must also be available in visible content or the disclosure.

### Metric definitions and denominators

Render the validated aggregate values, units, denominators, sample sizes and availability returned by FastAPI from the approved R result. The formulas below explain the measures to the reader. When the available result supplies a count without enough information to explain its denominator, show the approved count and identify the missing context. [TRD statistical ownership](../../TRD.md#5-statistical-analysis-and-reports) · [API metric and benchmark schemas](../../API.md) · [Metric definitions](https://scikit-learn.org/stable/modules/model_evaluation.html)

| Display | Definition and context |
|---|---|
| **Precision** | Of the frames in which RAFIQ predicted the behavior, the share where the reference label also says present. TP / (TP + FP). |
| **Recall** | Of the frames labeled present for that behavior, the share RAFIQ detected. TP / (TP + FN). |
| **F1 score** | Harmonic mean of precision and recall. Equivalent to 2TP / (2TP + FP + FN) when defined. Explain which counts affect it. |
| **Accuracy** | Correct present and absent predictions divided by all frames scored for that class. (TP + TN) / (TP + FP + FN + TN). Abundant absent frames can make accuracy appear high even when recall is low. |
| **Scored and unusable frames** | Match label and prediction timestamps at 10 Hz. The scored class count is TP + FP + FN + TN. Exclude frames unusable for that class from its confusion counts. Show the released unusable share with its sampled-frame base when available. A loss of the whole feed makes all evaluated classes unusable. |
| **Overall and per-class coverage** | Overall uses usable feed time. A behavior’s coverage uses time its cues were observable. Use elapsed session time with deliberate user pauses excluded and observation-loss pauses included. Label the time basis near each value. Coverage by time and unusable share by frame have distinct bases. |
| **False warnings per monitored hour** | Approved false-warning count divided by monitored hours. Show the monitored-hours base and the numerator when explicitly supplied. Count a combined warning once as false if none of its named behaviors matches a qualifying labeled episode. Frame-level false positives belong to the matrix. |
| **Warning delay** | Elapsed milliseconds from the labeled cue meeting its configured dwell to the visible warning. Label the statistic and the approved delay sample size when present. Treat `warningDelayP95Ms` and `warningDelay[p95]` as one statistic. Conflicting values require result validation before display. |

## States and contract gaps

| State | Presentation |
|---|---|
| **Loading** | Keep the shell, heading and return link. Use a compact, motionless placeholder with **Loading benchmark results**. Display a version here only if it is already known from an authorized reference. Announce the resolved state once. |
| **Approved** | Show released values and scope. A confirmed zero is `0`, `0%`, or `0 per monitored hour`, with a usable denominator where applicable. A measured zero may have a zero-length bar and a visible value label. |
| **Awaiting approval** | Use the API’s `pending` state and say **Benchmark results are awaiting approval.** Keep navigation and the plain-language scope description. Hide numbers, matrices and unapproved release details. |
| **Retrieval failed** | Say **Benchmark results could not be loaded.** Put **Retry** beside the message, repeating the read operation and retaining the report return path. Follow the shell’s existing authentication/eligibility recovery for 401/403 and its retry timing for rate limiting. |
| **Metric unavailable, incomplete, or withheld** | Keep the class row and other approved metrics where publishable. Represent `unavailable`, `incomplete` and `suppressed` in text with the approved reason where available. For `notQualified`, use **Unavailable · Not qualified** if that reason is meant for release. Neither an undefined ratio nor a withheld result produces a zero mark. Missing or empty scoring populations have a state in place of the score. All-zero count cells only represent authorized counts, with **No scored frames** if supported. Preserve suppression across the table, chart and readout. |
| **Approved payload lacks required evidence** | Keep authorized evidence that is usable. Identify unavailable metadata or sections in place. Do not substitute a newer result for an unresolved D18 reference. If the reference cannot resolve, keep the path back to that report. |

The documented `getBenchmark` operation returns one approved result or a pending state. Ship read-only version metadata. A future selector needs an approved release list, stable release IDs and authorized retrieval for a selected release, including the release cited by D18. Show **Benchmark version** only as a selector when multiple approved releases can be opened. Refresh scope, counts and metrics together on selection, with loading, unavailable release and retry states. Historical comparison deltas need separately approved comparable evidence. [Benchmark contract](../../API.md) · [Version selector reference](https://docs.github.com/en/get-started/using-github-docs/about-versions-of-github-docs)

The documented schema supplies monitored hours, dataset/annotation/scoring and catalog/model/policy versions, per-class confusion counts, and metric metadata. It lacks an explicit benchmark release ID, a structured held-out setting and actual held-out driver or staged-episode counts, and an explicit unusable-frame share/base and false-warning numerator. Confirm publication fields for these values before using them. Confirm metric denominator units, including time bases and the warning delay sample population, plus the precedence and consistency contract for the two p95 fields. The documented delay payload contains summary statistics. The full distribution belongs to release evidence until the driver contract provides approved distribution data. Keep PRD planning targets in methods if needed and identify them as protocol targets. [API schema](../../API.md) · [PRD measures and scope](../../PRD.md#83-benchmark-and-behavior-policy)

## Components and researched alternatives

- **Existing RAFIQ.** The read-only Pen.dev inventory shows **Review metric card** (`uw6Ef`), **Review measure selector** (`mCZsh`), **Exact-value readout** (`pmHUW`), **Behavior breakdown row** (`ucjJp`), and horizontal/stacked status rows (`Yh4JZ` / `fqIDy`). Reuse those treatments and the private shell. [RAFIQ Pen file](<../../../Pen Design/RAFIQ.pen>)
- **Standard.** Use a semantic table, disclosure button, retry button, navigation links, and plain-text readouts. Use an ordinary labeled select when the release contract supports it. Prefer a short definition trigger that works with focus and tap and a persistent definitions disclosure for complete content. Supplemental hover/focus text should be dismissible with Escape, hoverable and persistent while needed. [WAI disclosure](https://www.w3.org/WAI/ARIA/apg/patterns/disclosure/) · [WAI tooltip](https://www.w3.org/WAI/ARIA/apg/patterns/tooltip/) · [WCAG hover and focus](https://www.w3.org/WAI/WCAG22/Understanding/content-on-hover-or-focus.html)
- **New RAFIQ.** Use labeled horizontal score marks alongside a semantic data view, the per-behavior 2 × 2 confusion matrix and count readout, and a release scope block with exact version metadata. Keep these small and renderable with native HTML/CSS in Next.js and TypeScript. [Approved frontend](../../TRD.md)

### Chart patterns

| Pattern | Research and decision |
|---|---|
| **Interactive confusion matrix and heatmap** | Use scikit-learn’s class-wise binary mapping and Plotly’s labeled heatmap and click-event patterns as references. | **Precision, recall, F1 and horizontal comparison** | Use horizontal marks for readable behavior labels and a common baseline. Precision and recall show different failure modes at the same released operating point. F1 and accuracy have direct views. A precision–recall curve would imply threshold sweep data. Keep exact values, coverage and the relevant sample beside the marks. ## Pen review and acceptance

- Use `colors.canvas` (`#0e100f`), `colors.ink` (`#fffce1`) and `colors.accent-stone` for secondary text. Use Mori or the existing Space Grotesk substitute, a light heading weight, flat panels, `rounded.md` and 8/16/24 px token spacing. Use a restrained chart accent and established focus treatment with checked contrast. Avoid using color alone for counts, availability, and selection. [Design tokens](../../DESIGN.md) · [Accessibility floor](../../EXPERIENCE.md#accessibility-floor)
- For the eventual Pen handoff, represent approved, awaiting approval, loading, retrieval failure, and partial availability. Show wide and stacked frames, a selected behavior and cell, metric help and expanded methods. Label illustrative values as **Example data**. Pen frames can communicate layout and visual states. Frontend work provides real release binding, keyboard interactions, announcements, responsive tables, and reduced-motion behavior.
- In review, verify that a driver can identify the release and scope, compare the same measure across behaviors, name a miss and its count, find that behavior’s coverage and inspect the p95 basis. Verify that approved zero, unavailable, and awaiting approval are distinguishable by text. Check that the keyboard can operate the behavior control, four count buttons, definitions, exact data view, and retry with a visible focus indicator. Keep focus on the activating control for in-place updates and announce only the concise changed result. Test with long labels, absent data, at high zoom, on touch and with reduced motion.

**Approval requested:** choose **A** or **B** and **C04** for static interactions, or name the optional motion component IDs. Confirm **counts with a persistent cell explanation** or request a row-percentage view for separate contract review.
