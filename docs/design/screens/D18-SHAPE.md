# D18 Report review and export

**Operate · Layout and evidence component approved on 25 November 2026.** A signed-in, eligible driver opens a ready report from D17 or an authorized direct link. The driver checks what RAFIQ validated, follows the evidence behind a finding, and exports the same report snapshot as PDF or Word. Export is available once the snapshot is eligible. Draft correction, regeneration, and requests for a new version take place in the external MCP client. [D18 requirements](../../SCREENS.md#d18-report-review-and-export) · [Review journey](../../EXPERIENCE.md#j6-author-through-mcp-and-review-a-report)

## Approved layout

The approved selections are **A · Continuous report with section outline** and **D18-C02 · Animated Accordion evidence panels**. Use the standard **Export** menu and immediate download feedback. The timing, sizing and exact labels below are handoff specifications.

1. Reuse the private driver navigation with **Reports** current. Place **Back to reports** above the report header.
2. Put report title, type, source scope, generation time and expiry at the left of the header, with **Export** at the right. Place format status and download actions below the export control within the header.
3. On desktop, use a slim left rail for **On this report** and a wider continuous document column. The first finding and its key figure should appear in the first viewport when space permits. Readers can compare findings, methods and limitations in one scroll.
4. The outline uses links to rendered sections. At narrow widths or high zoom, stack report identity, export action and format status, **On this report** disclosure, then document. Close the outline disclosure after an explicit jump and focus the destination heading.
5. Keep one document scrollbar. A sticky outline can be used when every link remains reachable in the available height. Keep export feedback in the header flow and clear of the reading area.

## What the driver reviews

| Region | Content and behavior |
| --- | --- |
| Report identity | Use the snapshot title as the page heading. Label **Session report** or **Personal trend report**. Show generated and report-expiry timestamps with time zone. Identify the source session or covered period from frozen, displayable values. Show a public-facing version only when the server supplies one. Place input, method, and analysis versions beside the evidence they qualify. |
| Findings | Render checked claims and their figures in snapshot order. Keep label, value, unit, and the qualifier essential to interpretation visible together. Show relevant coverage, sample size, denominator and observation unit where supplied. Preserve reported precision and distinguish actual zero, unavailable and privacy-suppressed results. A long figure list may use a labeled table with exact values. Use typography and alignment for comparison. |
| Evidence panels | Put **Show evidence** below the relevant finding and include the finding name or ordinal in its accessible name. The expanded panel shows authorized references and figure provenance, with **View source** only where a stable mapping and eligible destination resolve. An in-report jump targets and focuses the source entry. An eligible linked session opens D07 with a return path to this finding. Preserve critical qualifiers outside the disclosure. |
| Methods, Sources and Limitations | Use real headings and render the validated content in document order. Methods uses supplied descriptions and versions, with scoped provenance where it applies. Sources uses authorized labels and stable references. Limitations remain visible in normal reading order, with any finding-specific qualifier adjacent to its figure when explicitly supplied. An empty section may say **No findings are listed in this report** or **No limitations are listed in this report** after a successful read of an otherwise valid snapshot. |
| Benchmark summary | For applicable general reports, embed the frozen approved aggregate with its version, scope, key figures, units and relevant limitations. Keep it distinct from personal findings. Show **View benchmark** only when D16 can resolve the cited release. D16 returns to the originating section after revalidating D18. An inapplicable benchmark leaves the section and outline entry out. A required summary missing from a supposedly ready snapshot is a validation issue. |

Use **On this report** as a navigation landmark. Links jump to real headings and move focus to the target on explicit activation. Mark the current section visually and with `aria-current="location"` where tracked. Passive scrolling leaves focus and announcements alone. Keep headings below sticky chrome. Restore the originating D17 row and scroll, or the Reports heading when the row is gone. On an authorized return from D07 or D16, restore the report position and open panels only after checking the same report again. ## Export and access states

**Export** opens a two-action menu with **Export PDF** and **Export Word (.docx)**. Selecting either requests that format for the report currently displayed. Both formats reproduce the validated findings, figures, sources, methods, limitations, and applicable benchmark, including content inside collapsed panels. PDF pagination and Word layout can differ. Place “Downloaded files stay under your control” beside the export controls, visible before the file is downloaded.

| Condition | Treatment and next action |
| --- | --- |
| Opening the report | Show **Loading report…** in the private shell with generic placeholders. Render title, metadata, contents and export controls only after authorization and snapshot validation. |
| Preparing | Close the format menu and restore focus to **Export**. Show **Preparing PDF…** or **Preparing Word document…** beside the action. Poll the server-provided status path as directed. Use indeterminate feedback. Guard duplicate requests for that format and keep the other format’s status independent. |
| Ready | Show **PDF ready to download** or **Word document ready to download** inline with an explicit **Download PDF** or **Download Word (.docx)** action. Start from the server-issued expiry and show the deadline with its time zone and a short “Link expires after 5 minutes” note. Announce availability once and leave focus where it is. |
| Download initiated | Hand file transfer to the browser while keeping the report and status visible. If initiation is confirmed, say **Download started**. The browser indicates transfer completion and local save. Keep a recoverable message if the attachment request is rejected or interrupted. |
| Export or status failure | Use a format-specific safe error and **Retry PDF export**, **Retry Word export**, or **Check export status** where eligible. Reconcile an uncertain request before starting another render. Preserve the reviewed snapshot and unaffected formats while access is still confirmed. |
| Download link expired | Remove the old download action and show **PDF download link expired** or its Word equivalent when expiry is confirmed. Offer **Get new PDF link** or **Get new Word link** only for the currently eligible owner and same snapshot. A fresh explicit request can reuse eligible bytes. Polling leaves link expiry unchanged. If expiry removes the focused download action, move focus to the replacement action or format status. |
| Hosted report expired | For a verified owner with an authorized lifecycle status, show **Report expired** and clear the preview, outline, cached evidence, and download actions. Explain that hosted access ended. **Back to reports** remains available. |
| Report withdrawn | When the verified owner may see the lifecycle reason, show **Report withdrawn** and clear the same content and actions immediately. Suggested copy “A required source was deleted or expired. Ask your external agent to create a new report using available sources.” Offer **Back to reports**, with **Open Connections** when the driver needs authorization guidance. This condition takes precedence over a ready export or expired link. |
| Access lost or unknown destination | Clear old-account data, open menus, and pending view updates. Use the existing identity flow if sign-in is required, then revalidate the destination. For missing, foreign, or otherwise inaccessible reports, use P08’s privacy-safe **This item is unavailable.** and its return link. Only show report-specific lifecycle copy to a currently authorized recipient of that status. |
| Temporary read failure | Show **Couldn’t load report** and **Retry** on recoverable failures. Use **You’re offline** when confirmed. If the snapshot’s current authorization cannot be established, withhold private content and export actions until a successful read. |

The hosted report expires at 30 days from creation or earlier loss of a required source. The owner-bound download link lasts five minutes and never extends the report’s lifetime. Check current account, conditions, action authority and source eligibility for review, export creation, status reads and every download request, including byte ranges. Source loss during rendering or while a download is ready invalidates delivery. Authoring grant loss during generation blocks publication. The owning service determines the status of a previously published snapshot. Route draft issues to D17 and external authoring. ## Visual and interaction details

- Reuse the D06 driver header and list-return behavior, D05 status rows and feedback, D15 method disclosure treatment, D16 benchmark conventions, and P08 unavailable presentation. The D16 proposal supplies the interaction pattern. Inspection of `Pen Design/RAFIQ.pen` confirmed D06 and D15 frames and existing variables, with D16–D18 treated here as design requirements or proposals.
- Use `colors.canvas`, `colors.ink`, `colors.accent-stone`, the existing Mori type hierarchy, and established status and focus treatments. Use color alongside plain text and icons. Start with the established 48 px wide and 20 px narrow gutters, `spacing.md` for related groups, and `spacing.xl` for section gaps and between columns. At 1440 px, start with a 200–224 px outline and a reading column around 65–75 characters wide for prose. Sizes are shaping targets. [Visual system](../../DESIGN.md) · [D17 proposal](D17-SHAPE.md)
- Show a 1440 px wide layout, 900 px laptop layout, and 390 and 320 CSS px reflow. Test 200% text zoom and 400% browser zoom where it produces 320 CSS px. Wrap long titles, zoned dates, versions and labels. Scroll a genuinely wide evidence table inside its own labeled, keyboard-accessible region. Use real headings, skip link, visible focus, semantic tables and text statuses.
- Evidence triggers use Enter and Space and retain focus. Each trigger has a distinct accessible name and expanded state. Keep closed content out of the tab order. A menu button opens with Enter or Space, arrow keys move among actions, and Escape returns focus to **Export**. Announce state transitions once with a polite status region. On confirmed removal of the document, focus the safe state heading. Link expiry updates the deadline and action without a per-second announcement.

## Evidence accordion motion

Use **D18-C02 · Animate UI Accordion (Radix UI)** in multiple-open mode so the driver can compare evidence across findings. Keep each claim and key figures visible above its accordion trigger. Use **Show evidence** and **Hide evidence** with a chevron and the finding-specific accessible name. Bind the disclosure to the current snapshot and finding. At initial load panels are closed. Restore a still-authorized navigation context immediately.

| Moment | Pen.dev storyboard | Frontend behavior |
| --- | --- | --- |
| Closed | Show the finding, essential figures and the focused or unfocused trigger. | The trigger exposes its collapsed state. Links inside the panel are outside keyboard navigation. |
| Open or close on activation | Use a 120–160 ms chevron turn and short reveal or collapse. Keep the finding and trigger in place. Show the two settled frames and annotate the transition. | Adapt the upstream height and opacity transition to RAFIQ. Remove blur. For tall content, reveal the layout immediately and use only the brief chevron cue to avoid shifting the reading position throughout the animation. On collapse, keep hidden links out of the tab order as soon as the panel is closing. |
| Reduced motion or restored navigation | Show the destination frame immediately, with the chevron and label at rest. | Bypass panel and chevron motion, including upstream fades and blur. Use the same structure, focus and access checks. |
| Expiry or access loss | Replace the document with the safe lifecycle or unavailable frame. | Remove private content and invalidate active or pending interactions immediately. Expiry and access loss bypass exit motion. |

The approved component supplies the interaction primitive. Use RAFIQ typography, chevrons, spacing and focus treatment. Pen.dev represents state and motion intent. The Next.js client provides the keyboard and screen-reader semantics, the reduced-motion branch, and the authorization and download lifecycle. ## Pattern research

| Pattern | Reference and application to D18 |
| --- | --- |
| Preview | Acrobat pairs a document area with page thumbnails and bookmarks. D18 borrows the document-plus-rail structure and uses a reflowing text preview, so findings and provenance remain searchable, selectable and readable at zoom across both output formats. [Adobe Acrobat](https://helpx.adobe.com/uk/acrobat/using/page-thumbnails-bookmarks-pdfs.html) |
| Section navigation | Google Docs builds a heading outline that jumps to document sections. D18 adapts heading-linked navigation to a read-only report with context-preserving returns. [Google Docs document outline](https://support.google.com/docs/answer/6367684?hl=en-en) |
| Export dropdown | Google Docs prompts for file type under **Download**. D18 brings the two format actions into a single top-level menu and keeps the later download action in a persistent status row. [Google Docs download workflow](https://support.google.com/docs/answer/49114?ctx=topic&hl=en&topic=21010) · [W3C menu button](https://www.w3.org/WAI/ARIA/apg/patterns/menu-button/) |
| Download feedback | Chrome shows its own transfer indicator and completion tray. RAFIQ shows preparation, readiness, eligibility and expiry, the parts it can verify. [Chrome downloads](https://support.google.com/chrome/answer/95759?hl=en) |
| Evidence panels | W3C’s disclosure places one trigger next to the information it reveals. D18 uses independent panels and leaves essential qualifiers visible in the main report. [W3C disclosure](https://www.w3.org/WAI/ARIA/apg/patterns/disclosure/) |

## Handoff questions and acceptance checks

- `ReportSnapshot` includes claims, evidence IDs, figures, provenance, source labels, limitations and nullable benchmark. The open contract items are evidence-ID-to-source mapping, explicit trend-period and coverage fields, a report-level method narrative, and a public-facing version. Use supplied displayable facts and provenance. Confirm a contract before adding exact source jumps or filling those metadata fields. A payload missing evidence needed to validate a finding should surface a safe unavailable state and prevent new exports until it is resolved.
- D16’s documented read provides the currently approved benchmark. Confirm how it can resolve a report’s cited release before enabling that link for older snapshots. D18 keeps the approved summary embedded in its snapshot.
- Confirm the authorized lifecycle response for a direct report destination. The detail operation documents a snapshot or standard errors. Map a generic 404 to P08 and use the specific withdrawal or expiry copy when the server provides authorized lifecycle information. [API contract](../../API.md)
- Use a short session fixture and a multi-finding trend fixture with long titles, multiple references, exact figures, an unavailable metric, limitations and an applicable benchmark. Label fixture values as synthetic. The implementation acceptance pass compares preview, PDF and DOCX for snapshot identity and content, including evidence inside closed disclosures. It also exercises both formats together, an expired link and reissue, source loss during preparation and after readiness, account change, and unknown direct links at desktop and reflow widths.
- Pen.dev frames should show the approved layout at desktop and reflow widths, collapsed and expanded evidence with focus and reduced-motion variants, the open export menu with both formats, preparing and ready together, failed and expired format states, and distinct withdrawn, expired and generic unavailable report frames. Annotate the authorization prerequisite for each lifecycle variant. Use the same synthetic snapshot across ready and download states so reviewers can check continuity.
