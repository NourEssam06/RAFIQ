# D13 What-If Result

Design proposal for approval. D13 is an **Operate** workspace for a signed-in driver reviewing a simulation of their own completed session. It opens when they start a run or select a saved run in D12. The driver should be able to see what changed under the selected thresholds, check which figures are backed by reference labels, and return to D12 to start another run. A saved result retains its original inputs, scope and versions. [Screen requirements](../../SCREENS.md#d13-what-if-result) · [Experience](../../EXPERIENCE.md#what-if-experiment-studio-and-benchmark) · [Replay eligibility](../../PRD.md#87-statistical-methods-and-data-access)

## Layout options

Both use the private shell with **Analysis** current and keep the full labels **Recorded baseline** and **Simulated result** in that order. The first viewport shows **Back to What-If**, the H1, run status, source date/time and zone, selected thresholds, measurement-series version, and analysis and policy versions where available. Let inputs wrap and show the first few thresholds with a **Show all thresholds** disclosure when needed. Keep **Change inputs** in D12, reachable from D13 when the source can still be selected. Back returns to the saved run row or submitted inputs where available.

## What each comparison can say

- Read the saved replay's source, thresholds, provenance and validated comparison rows. Pair by metric code and returned behavior or overall scope. Show units, scope, denominators and sample counts where supplied. Label counts and rates precisely, such as **Warnings** and **Incidents per monitored hour** when the returned unit supports that label. Descriptive results can be shown without reference labels. Captured warnings and simulated warnings are separate outcomes.
- Show **precision, recall, accuracy, false alarms and missed detections** only for scopes and sides supported by compatible reference labels and the returned metric status. When labels are absent, use one section-level message such as **Reference labels are unavailable for this replay, so detection quality cannot be evaluated.** Omit all five metric rows in that case. When labels support some metrics or sides, keep eligible values and give each unavailable side its own reason where supplied, such as **Unavailable · insufficient labeled observations**. Keep false alarms distinct from the descriptive warning count.
- An available `0` renders as **0** with its unit and scope. For unavailable, incomplete or suppressed values, show the appropriate text and authorized reason. A chart may mark a measured zero at the origin, while an unavailable value has no mark and a text reason. Reserve blank numeric cells for skeletons during loading.
- Label the comparison **Difference (simulated minus recorded)**. Show a signed absolute difference only when both values are available and the definition, unit, scope and scoring or exposure basis are comparable. Use count units for counts, the rate unit for rates, and percentage points for percentages. Retain available values with an explanation when a difference is unavailable. A true tie reads **No difference**. If a nonzero difference falls below display precision, increase precision or give an explicit bound. Use neutral signs and text. A change in alert volume or a mixed shift in precision and recall cannot establish an overall improvement or safer driving.
- For grouped bars, display one measure and unit at a time with matched domains, a common zero origin and stable row order. If a pair is incomparable, keep its eligible exact values in the data view and withhold the grouped marks for that pair. Avoid inventing time bins, a threshold curve or a before/after timeline from aggregate rows. Surface an always-reachable **View exact values** link to a named table with row and column headers, units and reasons. Match any pointer readout with keyboard access to the same values. ## Run states and transitions

| State | Presentation and recovery |
| --- | --- |
| Opening a saved run | Keep the heading and navigation available. Show **Loading result** and a neutral skeleton while current access is checked. |
| Queued / Processing | Use the actual status text and known submitted context. Reserve the comparison area for the result. Show a progress percentage only if the service supplies one. |
| Ready | Render authorized context and final numbers together. Show label-free, partial or fully scored results according to the available evidence. If the ready payload supplies no eligible figures, explain why where supplied and offer a way back to D12. |
| Transient run failure | Offer **Retry simulation** with the same source and thresholds after eligibility is checked. If only the result fetch failed, **Retry loading result** checks the same saved run. Keep both actions scoped to their operation. |
| Invalid inputs | Explain the affected input where known and link back to D12 with eligible fields retained. |
| Source expired, withdrawn or inaccessible | Clear the comparison and any withdrawn source details immediately. Use the authorized reason if safe to show and return the driver to What-If or source selection. |

For the optional motion treatment, replace the skeleton with the final comparison immediately on **Ready** and use a single 160 ms ease-out fade on an accent or placeholder overlay. A chart measure change can refresh a selection accent for 140 ms while the new title, marks, exact values and table update together. Keep the shell, focus and column positions stable. Open already-ready saved runs directly. Use a polite status region for meaningful changes, announcing **Simulation ready** once and leaving focus with the driver. Use immediate visual changes with reduced motion, including for the overlay. [D13 states](../../SCREENS.md#d13-what-if-result) · [Experience accessibility](../../EXPERIENCE.md#accessibility-floor)

- Plan a 1440 px desktop, a narrow reference and a check at 200% zoom plus 320 CSS px. Keep the source, state, retry and return actions visible. Let the exact-value table scroll only in a labeled region when needed, with a stacked equivalent that preserves metric → recorded → simulated → difference reading order. Use a meaningful H1, visible focus, and text alongside status and series styling.
- Depict opening, queued, processing, ready without labels, ready with labels, partial or incomparable, eligible retry, invalid inputs and unavailable source. Show the finished comparison, static and reduced-motion states in Pen. Frontend verification covers asynchronous status, permission withdrawal, keyboard navigation, accessible table and status announcements, and motion preferences.
- Use explicitly synthetic figures in frames. An illustrative descriptive pair is **2 → 3 incidents**, **1 → 2 warnings**, and **10 → 15 incidents per monitored hour** over the same 12 monitored minutes. A separate fictional scored fixture on 100 compatible reference observations can show **80% → 75% precision**, **40% → 60% recall**, **86% → 88% accuracy**, **2 → 4 false alarms** and **12 → 8 missed detections**. These figures deliberately move in mixed directions. Show a measured zero and an unavailable value in a separate variant.
- The proposed `SimulationRun` response has `result: null` before completion. It does not carry the pending input snapshot needed to re-open a queued run with source and threshold context. Confirm the authorized pending snapshot, same-input retry contract and comparability metadata with the API owner. If the contract omits any field, show only known context and omit unsupported differences. Treat the run-level `hasReferenceLabels` flag as a gate and use per-metric availability to decide what each side can show. ## Decisions for approval

1. **Layout A** for an exact-value workspace or **Layout B** for a chart-led comparison.
2. **C01 + C02** for the paired KPI and difference. Select **C03** for native comparison bars, **C04** for the shared-renderer alternative, or omit the optional chart in A. **C08** is an optional card shell.
3. **C06** for the brief CSS ready reveal or **Static** for immediate state changes. **C05** and **C07** are Motion alternatives. Any treatment uses immediate values and a static reduced-motion state.
