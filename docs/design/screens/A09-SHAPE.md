# A09 Audit

Approved Pen.dev handoff · 25 November 2026 · Operate mode

An authorized RAFIQ Owner uses Audit to find and verify an administrative access or support event from the last 90 days, including failed lookups and failed or denied actions. Success means the Owner can narrow the record set, identify who did what and when, read the outcome, and continue to older records. The workspace is read-only. [A09 screen requirements](../../SCREENS.md#a09-audit) · [FR-22](../../PRD.md#57-admin-dashboard) · [Admin experience](../../EXPERIENCE.md#admin-workflows)

## Approved direction

The Owner approved a filter bar above the table, authorized details on demand, and static filters and loading with a 120 ms fade when details open. The table is the focal point. The filter rail considered during shaping would have kept controls beside the results while reducing space for timestamps and references. The approved bar gives the table the full content width and wraps in reading order. Use existing RAFIQ controls and standard states as specified below. External examples are research references with component IDs for any later selection.

## Frame and hierarchy

1. **Admin shell.** Enter through **Audit** in the separate, permission-scoped administration navigation. Mark Audit current. A protected direct link waits for current Owner authority and session-bound MFA before showing data. Leave through the available admin navigation, including **Staff Access** and **Account Support** where authorized. A08 and A07 write actions that can appear in Audit. The audit records have no links into driver workspaces or privileged action flows.
2. **Heading and scope.** Use **Audit**, followed by **Audit records are retained for 90 days.** Show the display time zone next to the results heading or timestamp header so it applies to both the table and date filter. Use **Audit records** for the results region and **Newest first** as a readable ordering cue.
3. **Filter bar.** Keep persistent labels in order **Staff member**, **Action**, **Outcome**, and **Date**, followed by **Apply filters** and **Clear filters**. Defaults are **All staff**, **All actions**, **All outcomes**, and **Last 90 days**. Place the date range inputs directly below their label when a custom range is open. Keep applied values visible when drafts differ. Use compact text for an applied summary only while there are unapplied edits or when the controls are collapsed on a narrow layout.
4. **Results.** Use one semantic table with columns **Timestamp**, **Actor**, **Action**, **Target reference**, and **Outcome**. Keep rows newest first and headers static. A row with authorized details gets a separately focusable **Details** disclosure in a trailing column. Align timestamps and statuses consistently, wrap long values, and give actions enough width for readable labels. Use outcome text **Succeeded**, **Failed**, or **Denied** with a supporting icon. The absent target reference reads **No target shown**. An unsuccessful lookup can still be a record even when the target is absent.
5. **Pagination.** Place **Newer records** and **Older records** below the table in reading order. An optional count describes only the current page, for example **25 records on this page**. The first page has no newer destination. Enable older only when the response supplies a next cursor. An accepted page change closes the open disclosure.

## Filters, dates and pagination

| Control | Behavior |
| --- | --- |
| Staff member | Single choice of authorized audit actors, including Owners and eligible historical staff. Submit the opaque `actorId`. Use an authorized display label if supplied. The API currently supplies an opaque ID, which is the supported fallback. Never derive a name or email from the ID. Keep this filter tied to audit actors, independent of driver search. |
| Action | Single choice from the recognized backend action catalog. Use readable labels, for example **Account lookup** or **Suspend account**. Send the recognized value as `action`. |
| Outcome | Single choice of **Succeeded**, **Failed**, and **Denied**. Use the same mapping in the table and filter. |
| Date | Default to the server's full rolling 90-day scope. Show absolute timestamps with date, time and a clearly labeled display zone. Interpret **From** and **Through** as inclusive calendar dates in that zone. Send the start of the **From** day as inclusive UTC `from` and the start of the calendar day after **Through** as exclusive UTC `before`. Bound the date picker to days intersecting the retained window. The server enforces the exact retention cutoff, including partial days. Identify inverted, future, and out-of-range dates inline before submission. Pen examples use UTC for illustration until the admin display zone is defined. |

Changing a draft does not submit. **Apply filters** submits all four effective filters together and starts at the newest page. **Clear filters** restores the default scope and starts at the newest page. Preserve valid inputs across retry. Use the current response to update rows, active filters, pagination and any page count together. Match late responses to the current query and authority before rendering them.

Use the audit API's server-side filtering and fixed reverse chronological order. Use its proposed 25-record default. For **Older records**, fetch the server's opaque `nextCursor`. For **Newer records**, refetch using the prior request cursor recorded in a temporary stack for this authorized view, with a cursorless first page. Keep only the cursors needed for navigation, clear the stack on scope change or access loss, and use neither fabricated page totals nor page-number jumps. If an old cursor becomes unusable as retention advances, offer **Return to newest records** within the applied filters. Recheck authorization and retention on every read, including paginating back and restoring browser history. ## Authorized row details and privacy

- Show **Details** only if the current authorized response contains a display-eligible `reasonCode` or `requestId`. Reveal only the authorized fields beneath that row. Map approved suspension and reinstatement reason codes to their approved labels. Label the opaque correlation value **Request ID**. Keep both out of the default columns. Use a companion table row spanning the table or an inline region beneath a narrow record. The row itself is static.
- Render **Target reference** only from the server's permitted opaque projection. The endpoint enforces linked-identifier deletion rules. Keep unmatched lookup emails, account contact fields, tokens, invitation and recovery codes, credential material, message payloads, free-text reasons, and all private driving data outside the view and its filter options. Audit records are append-only for their retention period. The view offers filter, detail, and page controls.
- Apply **immediate access loss** on a revoked Owner grant, invalidated admin session, sign-out, or other established loss of authority. Clear and unmount rows, open details, staff options, filter values, pagination state and pending results. Abort in-flight reads and ignore any replies racing the clear. Remove Audit from navigation when the grant no longer permits it. Move focus to the destination heading and follow the allowed admin route, verification flow, or A01 no-access state. Access-loss transitions are instantaneous, including when details are mid-fade. Audit responses are private and uncached. Browser Back and tab restoration require current authorization before repopulating the view. ## States and recovery

| State | Presentation |
| --- | --- |
| Initial read | Once access is established, keep heading and controls visible. Show **Loading audit records…** with a few static, noninteractive placeholders aligned to the columns. Hide the placeholder shapes from assistive technology and mark the results region busy. |
| Applying filters or paging | Leave the surrounding layout and submitted values in place. Swap the result rows for the static loading treatment until the requested page arrives. Independently preserve draft input. Block duplicate requests for the same pending action and keep the initiating control reachable. |
| Loaded | Show the server-authorized records with their outcome labels and available pagination. Announce completion once, using the count for the current page where helpful. |
| Filtered empty | **No audit records match these filters.** Keep the applied filters visible and offer **Clear filters**. |
| Default scope empty | **No audit activity in the last 90 days.** Keep the scope visible. |
| Validation error | Keep valid inputs and the last confirmed result labelled with its applied filters. Associate date errors with the fields and focus the first invalid field or linked error summary. |
| Read failure | **Couldn’t load audit records.** Offer **Retry** for the same authorized query and page. Retain valid filter input. For rate limits, honor the server retry time. Treat failed actor-option loading independently and offer retry in that control. A permission denial takes the access-loss path. |
| Empty older page or expired cursor | Explain that older records are no longer available in this view and offer **Return to newest records** for the same filters. |
| Access lost | Clear the protected workspace immediately, then use the safe admin destination. For a dedicated fallback, use **You no longer have access to Audit.** |

## Motion and accessibility

| Moment | Standard motion | Reduced motion |
| --- | --- | --- |
| Filters, loading and page results | Immediate, with a static placeholder and status text during reads. | Immediate. |
| Open authorized details | Insert the panel at final size immediately. Fade its contents in over **120 ms**, ease-out. Keep text, icon position and layout stable once open. | Present the final panel and contents immediately. |
| Close details or lose access | Remove contents immediately. | Remove contents immediately. |

Use a labelled native button with `aria-expanded` and a stable association with its panel. Enter and Space activate it. Tab order follows the reading order. Give the repeated **Details** buttons distinct accessible names using authorized row context. On normal close, keep focus on the trigger or return it there if it was inside the panel. When the focused control disappears during paging, move focus to the results heading or nearest valid page control. Announce loading and results changes once. Use a visible focus treatment, labelled filters, table headers, and text outcomes that remain legible without color. Keep the narrow record view in date, actor, action, target, outcome, and details order with programmatically available field labels. ## Pen.dev boards and implementation checks

- Draw **1440 px** desktop with the complete filter bar, mixed outcomes, one missing target, a record with authorized details, and older-page navigation. Include an applied filter view with both page directions. Use synthetic opaque identifiers and outcomes. Draw **1024 px** narrow desktop with wrapped controls and **320 CSS px** reflow with labelled stacked records and no viewport-wide horizontal scroll. Check **200% browser zoom** and the 320 CSS px equivalent in frontend verification. [WCAG reflow](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html)
- Draw the detail storyboard as **Closed**, **Opened at final size, 0 ms**, **Visible, 120 ms**, and **Reduced motion, visible immediately**. Add one sheet for initial loading, filter loading, no matches, no activity, retry, unavailable older records and cleared access. Include visible keyboard focus on a filter and a detail trigger. Use visual variants for snapshots. Runtime policy, cursor behavior, keyboard focus, reduced-motion detection and live announcements are frontend work.
- Walk through a successful suspension, an unmatched lookup with a missing target and no submitted value, a denied action, and a row with an approved detail. Verify that filtering combines conditions, clearing resets scope, the displayed zone and calendar bounds agree, back and forward paging preserve newest-first ordering, and the server excludes records outside retention even when revisiting a page. Test equal timestamps across a page boundary with stable server ordering.
- Exercise a non-Owner deep link and revoke Owner access in a second session while the first tab displays an open detail and has a request pending. Verify that the first tab clears immediately, that late results and browser Back cannot restore private content, and that expired or deleted linked identifiers cannot reappear through the filter or details. Confirm the static and animated paths with keyboard and a screen reader.

The proposed API provides opaque actor IDs, recognized action strings, outcomes, time, opaque targets, approved reason codes and request IDs. The admin display zone, action label catalog, display-safe reason labels, and source of filter options for historical actors still need confirmation with the owning contract. The documented staff endpoint supplies IDs and role/state, but its coverage of all historical audit actors is unspecified. The mechanism that delivers revocation to an already-open idle tab also needs runtime qualification. These are implementation inputs. The Pen boards use synthetic labels and data and show the cleared state directly.
