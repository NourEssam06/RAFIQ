# A01 Admin Entry and Invitation

**Mode** · Operate. **Approved** · Layout A, a single-column staff entry, and A01-C01, Motion for React `AnimatePresence` for the decorative validation cue. Show the current verified account’s email in the invitation review. After sign-in, direct staff with unavailable invitations to a RAFIQ Owner.

Returning Owners and Staff arrive from the internal sign-in page. New staff arrive through an Owner-issued invitation link. A01 establishes verified identity and resolves the next eligible step. A02 owns authenticator enrollment and challenge. A03 owns MFA recovery from A02. A08 owns invitation creation and staff permissions. After verified MFA, open Service Health when permitted or the first currently permitted admin view. The support-only example opens Account Support. ## Approved layout

1. **Shell.** Use the P07/P08 access shell with the static RAFIQ wordmark, hairline divider, and a single centered, left-aligned content column in the upper part of the page. The first heading establishes staff context. Keep the same content origin for the form, invitation review, and denied states. The page excludes public signup and admin navigation before admission.
2. **Sign-in.** Use **Staff sign in** and “Staff access is by invitation.” For invite entry add “Sign in with the email that received the invitation.” Reuse P04’s visible **Email address** and **Password** labels, password reveal, field feedback and **Sign in** action. Show staff-supported identity methods and recovery actions only when their flows are confirmed for this surface. Return from verified identity to the appropriate internal entry or the pending invitation. Keep admin MFA recovery in A02/A03.
3. **Invitation review.** Use **Staff invitation**, then **Signed in as** and the verified current account’s email. Place the invitation status and its applicable action beneath the identity. The matched state leads with **Accept invitation** and offers **Use a different account**. Explain the handoff in one line, “Next, set up your authenticator app.” Use `omar@example.net` as a design fixture. Allow long addresses to wrap in the identity row. Keep the invited recipient’s identity and grant details private.
4. **Unavailable and access-denied states.** Reuse P07/P08’s text-first status treatment with one heading, a short reason, and the applicable way forward. Style Owner guidance as text until there is an approved contact destination. Keep **Staff sign in**, **Use a different account**, and **Sign out** specific to the state.

## States and copy

| State | Visible treatment and action |
| --- | --- |
| Signed out | Show the staff form. From an invite, give the matching-email instruction and retain the pending invitation through the approved sign-in flow. |
| Identity pending, rejected, or unverified | Use P04’s submit and error treatments. Show safe credential feedback, retain the email where appropriate, and follow Clerk’s verified identity path. Enable invitation review after verification. |
| Checking invitation | Show **Checking invitation…** with the pending cue. Keep the **Accept invitation** action unavailable while the outcome is unresolved. |
| Eligible invitation | Show **Invitation ready to accept**, the current verified email, **Accept invitation**, and **Use a different account**. Accept only from an explicit action. |
| Accepting | Show **Accepting invitation…**. Allow one submission at a time. On confirmed redemption, move to A02 enrollment. |
| Wrong account | Show **Use the account that received this invitation** and the current email. Offer **Use a different account**. Recheck the new verified identity before offering acceptance. |
| Expired, already used, or invalid | Use a specific heading when the server can safely disclose the result. Otherwise show **This invitation is unavailable**. For signed-in staff, use “Contact a RAFIQ Owner for help with your invitation.” On a used link, offer **Staff sign in** where applicable so an eligible account can resume through normal entry. |
| Temporary failure | Show **We couldn’t check the invitation** and **Try again** for a retryable check. If a redemption response is lost, show **We couldn’t confirm acceptance** and resolve current entry state before another attempt. Show retry timing only when the backend supplies it. |
| Verified returning admin | Continue to A02 challenge when required. Use current session-bound MFA and the current grant to resolve the destination. |
| No current grant or revoked access | Show **Staff access required** or, when safely confirmed, **Staff access has been removed**. Offer **Sign out**. Remove privileged content and controls immediately whenever the grant is revoked. |
| No permitted views | Show **You don’t have access to any admin views** and **Sign out**. Keep the admin shell out of the route until admission succeeds. |

**Contract to confirm before implementation.** The documented admin entry operation resolves account entry state. Invitation redemption binds and consumes the invitation. The current API does not clearly specify a read-only check for the pending invitation or safe typed outcomes for expired, used, invalid, and mismatched invitations before acceptance. Treat distinct design frames as fixtures until the backend confirms that contract. Confirm how the invitation survives identity changes and how an ambiguous redemption resumes. Use server-authorized outcomes for eligibility, the current grant, and the destination. ## Approved motion · A01-C01

| Storyboard beat | Pencil representation | Frontend behavior |
| --- | --- | --- |
| Pending | Show the compact arc and **Checking invitation…** in the stable status row. | Render the status as soon as the check starts. Expose the status as polite text and hide its decorative cue from assistive technology. |
| Server result | Show paired checking/result frames with a fixed icon slot. Annotate a single **140 ms ease-out** crossfade for the outgoing and incoming decorative cues. | Use `AnimatePresence` from `motion/react` around the cue only. Keep its footprint fixed and animate opacity. Update meaningful text, focus, and actions immediately, independently of animation callbacks. |
| Reduced motion or authorization loss | Show the final cue and text in a single frame. | Reduced motion swaps the cue immediately and holds any pending arc static. Revocation, sign-out, and terminal access changes remove the old state immediately. |

The 140 ms timing is the handoff default within the proposed 120–160 ms range. Use a small Next.js client component for the `motion` package. Gate the cue with `useReducedMotion`. Pencil specifies the visible beats and timing. React owns mount/exit behavior. Core Motion is free under MIT. Include its copyright and permission notices when distributing covered code. ## Acceptance checks

- **Pen.dev review.** Draw standalone sign-in, eligible invitation, and no-permitted-view frames. Include a 1024 px checking frame, a 390 px invitation review, and a 320 px wrong-account example with a long email. Cover identity feedback, expiry, used, invalid, retry, revocation, and sign-out in a state board. Add the three motion beats and a visible keyboard-focus example. Use synthetic data and label the A02/A07 handoffs in annotations.
- **Keyboard and assistive technology.** Verify meaningful page title, one main heading, labeled fields, natural focus order, and visible focus. Associate field errors with their inputs. Allow paste, autofill, password managers, and keyboard activation. Announce meaningful inline outcomes once without stealing focus. On page replacement or removal of the focused action, move focus to the replacement heading. Check contrast, text zoom at 200%, and reflow at 320 CSS px. Change the grant while A02 or a privileged view is open and verify immediate withdrawal of access.
