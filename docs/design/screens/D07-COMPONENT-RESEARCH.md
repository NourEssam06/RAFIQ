# D07 Session Detail — shaping proposal

**For approval · Impeccable Operate mode · 25 November 2026**

The signed-in driver needs to answer three questions about one completed session. What did RAFIQ observe? How much of the session could it observe? What happened at a particular moment? A successful review lets the driver verify the coverage denominator, find a warning or recorded Emergency Mode outcome by its exact time, and open the supporting evidence with a keyboard. Use D07 for the private post-session review. [Screen specification](../../SCREENS.md#d07-session-detail) · [Product requirements](../../PRD.md#55-personal-analytics-simulation-and-controlled-experiments)

### A · Full-width timeline with inline evidence — recommended

Use the full content width for the plot. Show the selected D08 evidence panel directly below it and above the chronological event list. Close the panel to return to the source control. Put the full-session breakdown and duration distribution after the event list. Use two lower columns only when labels, scales and exact values fit. The wider plot gives short detections and close markers more space. There is more vertical travel between the timeline and the lower charts when evidence is open. It follows the approved D01 review order and gives D07 a dedicated evidence slot.

```text
Session Detail                                  Personal Overview   What-If*
Session date · start–end · zone · review status · versions
Monitored time | Incidents | Time with detected behavior | Coverage | Warnings
Timeline · visible range · Earlier / Later · Zoom in / out · Reset zoom
Observation / behavior lanes / event markers                              →
Selected occurrence · D08 evidence panel                          [Close]
Chronological events · elapsed time and event type
Behavior breakdown [Count / Duration]  |  Detection duration distribution
Session actions                                              Delete session
```

### B · Timeline with an event and evidence rail

Use the same header and KPI strip. On wide desktop, place the timeline next to a bounded event rail. The rail shows the chronological list and puts the selected D08 panel directly after its row. Keep both the range controls and the selected timestamp visible when evidence opens. Below the workspace, use the same two analysis panels and secondary session actions. This favors repeated incident triage with the list and plot simultaneously visible. The plot has less room for overlaps and grouped markers, and the rail needs an earlier reflow threshold. At narrow widths and high zoom, use A's single-column order and keep the same selection and range.

```text
Session Detail and session metadata              Personal Overview   What-If*
Monitored time | Incidents | Time with detected behavior | Coverage | Warnings
Timeline · visible range · controls             | Chronological events
Observation / behavior lanes / event markers    | Selected row + D08 evidence
Behavior breakdown [Count / Duration]           | Detection duration distribution
Session actions                                                 Delete session
```

\* What-If appears when this specific session is an eligible source.

### Full-session KPI strip

| Order | Card | Display rule |
| --- | --- | --- |
| 1 | Monitored time | Use elapsed monitored time. Exclude deliberate pauses and include observation-loss pauses. Keep this figure distinct from wall-clock session duration. |
| 2 | Incidents | Show distinct incidents and incidents per monitored hour. One incident containing several behaviors counts once. |
| 3 | Time with detected behavior | Show the usable detected-time union and its share of monitored time. Count overlapping behaviors once in the union. |
| 4 | Observation coverage | Show usable-feed time, monitored time and their ratio. Use the unrounded result or authoritative `belowTarget` to show **Low coverage** below 90%. Keep the label readable alongside the displayed percentage, including when rounding approaches 90%. |
| 5 | Warnings | Show distinct issued warnings. A combined warning counts once. |

Set the scope to **Full session** on the KPI strip and the lower charts. Use stable, left-aligned numbers, consistent units and tabular figures where the font supports them. Keep exact durations available to the precision supplied by the API. Show clear display precision for derived ratios and rates, supported by the denominator and exact underlying counts or times when provided. Use approved R results through FastAPI. A viewport change leaves all five cards and lower charts in the same scope. ### Timeline, event markers and exact evidence

- Use one axis labeled **Elapsed time since session start** and retain clock pauses on that axis. Align the observation, behavior and event tracks to one scale. Give every detected behavior its own row. Show exact interval start, end and duration. Clip marks visually at range edges and expose original bounds in the readout and data view. Use aligned tracks to reveal overlap.
- Show known usable observation with zero detections as a labeled neutral interval. Use a different pattern and label for **Deliberate pause** and **Observation lost**, with authorized reasons when provided. For a behavior with unavailable cues during a usable-feed interval, show **Behavior observation unavailable** in the applicable track or data row. Treat uncovered bounds in a retrieved window as **Observation record missing** only when the record contract establishes that gap. Give a window still loading or failing its own status.
- Use text labels and different symbols for incidents, issued warnings and recorded Emergency Mode entries. Represent actual status changes with recorded labels. Emergency markers offer evidence review. At overview scale, a cluster displays its count and opens a bounded ordered set or a view that separates its members. Preserve every timestamp and event ID in the ordered list. Keep warning and emergency types identifiable when they share a time. Use deterministic ordering for ties and keep the selection crosshair, row, and panel in agreement.
- Start with the full-session time domain. Show the current bounds and **Zoom in**, **Zoom out**, **Reset zoom**, **Earlier** and **Later**. Proposed behavior is a bounded zoom around the selected occurrence when it lies in range, otherwise around the current midpoint. Earlier and Later move by a predictable window step. Reset restores the initial overview. Support the same operations by pointer and keyboard through buttons, with endpoint states and a custom range or scrubber only if needed later. Keep browser zoom and scrolling available. Update the range immediately for a confirmed window and use localized status while fetching. Announce each committed view change once.
- Make an ordered list of incidents, warnings and Emergency Mode entries equivalent to the interactive markers. Show the visible range above the list and keep its scope in sync with the plot. Give evidence rows exact elapsed time, event type and recorded label, with local time where useful. Open the same D08 panel from a mark or row. In the plot, use a single keyboard entry to a managed set of marks with arrow navigation and Enter/Space for activation. Keep the originating occurrence focused and marked as current when the panel opens. Provide a nearby **Read selected details** jump and a return target. From a valid deep link, load the containing window, select the occurrence and focus its marker or equivalent row. When a range move excludes the occurrence, label the selected time in the panel and provide **Back to selected time**. Offer a separate interval data view with observation and original detection bounds.

### Behavior breakdown and detection durations

| Element | Specification |
| --- | --- |
| Horizontal breakdown bars | Use a stable behavior order through **Count / Duration** changes. **Count** is constituent detections by behavior. **Duration** is each behavior's union of usable time. Show the exact current value and unit beside each bar, and show behavior-level coverage where supplied. Use a common zero baseline for the displayed measure. The two measures use their own labeled scales. Provide a data table with both values and availability. A confirmed zero has a textual value. An unavailable class has a reason and no quantitative mark. |
| Count / Duration | Use a labeled single-select radio group styled as segments, with Count initially selected in a fresh review. Tab into the group, arrows change selection, and the visible selection and chart header update together. Keep focus distinct from the selection treatment. No effect on timeline, KPIs or duration distribution. |
| Individual durations, 0–30 samples | Use a dot/strip plot grouped by behavior on a seconds axis and show the total matching `n`. Stack coincident marks away from the time axis or show an exact multiplicity, with the same samples represented in the table. A focused or selected point exposes behavior and exact duration. Label available descriptive statistics with the statistic, units and sample size. |
| Binned durations, 31+ samples | Use the authoritative count per behavior for **0–<2 s**, **2–<5 s**, **5–<10 s**, **10–<30 s**, **30 s or longer**. Treat ranges as ordered categories of equal visual width, with a shared integer count scale. Label the final category explicitly. The equal widths encode categories and the heights encode counts. Small multiples can keep behaviors readable on narrow screens. Focus or select a bar to show behavior, range, count and matching sample size. Offer a table with the same bins, exact counts and availability. No client rebinning or sample reconstruction. |
| Exact-value interaction | Make the readout available on focus, pointer hover and click/tap selection. Click/tap or Enter/Space opens a persistent inline readout when useful. Keep the transient tooltip supplemental, anchored, dismissible with Escape and persistent while hovered or focused. Keep interactive content in the inline detail and make exact values independently available in the tables. Use row or mark keys based on the source identity where available. |

The individual distribution wire samples carry `behavior` and `durationMs`. Present them as samples. The sample payload cannot identify the source incident for drill-down. ## Availability, recovery and deletion

| State | Presentation and recovery |
| --- | --- |
| Loading, syncing or processing | Retain authorized session context and reserve space with still placeholders. Separate loading from syncing and processing. Offer **View session status** to D05 for eligible recovery. Name the affected region and announce meaningful changes once. |
| Ready with confirmed zero | With usable exposure and an authoritative zero, show `0` and the unit. Explain **No detections recorded during usable observation** when applicable. Keep the usable timeline and the distribution's `n = 0` visible. |
| Unavailable behavior class | Show **Unavailable** with the authorized reason where supplied. E.g., no usable cues for that class. Other measured classes and overall coverage can remain available. |
| No usable observations | Where monitored exposure is positive and the record is complete, show measured coverage as `0%`, with zero usable time and the monitored-time denominator. Explain **No usable observations** and keep observation-dependent measures in their returned unavailable state. Independently recorded and authorized events can remain visible. |
| No monitored exposure | Show `0` monitored time where known. Ratios and rates with zero denominator show **Unavailable · No monitored exposure**. Preserve the server's per-metric availability for other values. |
| Missing data or unconfirmed outcome | Use specific text, for example **Observation record missing** or **Delivery unconfirmed**, when supported. Preserve available evidence. A missing optional clip leaves the metrics, timeline and incident description available. |
| Temporary failure or partial retrieval | Offer **Retry** in the affected section. Preserve authorized unaffected data and the active range. If prior data remains on screen, identify its scope and status. Prefer P07 or P08 where restricted or unavailable-link handling applies and clear private results and saved focus context when authorization is lost. |
| Deletion | Put **Delete session** in the secondary session-actions area. The confirmation names the session by date, time and zone and describes the loss of its incidents and clips and withdrawal of dependent hosted reports. Explain downloaded-copy retention. Show a pending state without duplicate submission, an inline retryable failure where eligible, and a confirmed **Session deleted** status before returning to D06. Focus the nearest surviving row or Sessions heading. Show dependency counts only when supplied by an authorized source. |

## Contract questions to resolve before build

- **Exact usable time and reasons.** The proposed coverage metric exposes a ratio and denominator. Confirm an explicit exact usable-time numerator or a precision contract that guarantees lossless derivation. Confirm typed reasons or evidence for unavailable classes, zero usable observations and missing records. Results with an unknown numerator need a clear unavailable detail while keeping the measured ratio visible where authorized.
- **Timeline bounds and event identity.** The timeline operation accepts bounded half-open windows and preserves original bounds. Confirm the maximum window and how an eligible full-session overview and accessible ordered list are assembled across bounded windows, including dense markers and a possible terminal event. Gate composite views on the required inputs so independently fetched revisions cannot appear as one consistent result when they differ.
- **Eligibility and deletion.** Use the current compatible-source list or an approved per-session capability to expose What-If. Confirm how D07 resolves eligibility off the current source-list page. ## Decisions for approval

1. **Layout** — A, full-width timeline with inline D08 evidence (recommended), or B, timeline with evidence rail.
2. **Components and motion** — RAFIQ components with the brief selection accent (recommended), all static, or selected candidate IDs from the research table. All options retain the same data and keyboard interactions.
3. **Timeline range** — named zoom and range buttons (recommended), or the same buttons plus optional pointer drag using D07-C03.
