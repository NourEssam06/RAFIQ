# D20 monitoring settings component research

These are candidates for approval. The recommended treatment is the existing RAFIQ form vocabulary with short CSS transitions where they clarify a change. The static equivalents below are available for every control. Driver actions, visible state, consent enforcement and save confirmation have their own behavior regardless of motion. [D20 proposed shape](D20-SHAPE.md)

## Source, cost and compatibility

- **A · Animate UI.** Each linked page includes a live example and readable React/TypeScript usage and styling. The docs link to the public source repository. The repository license allows free use in an app, including commercial use, requires keeping the copyright and permission notices with copies or substantial portions, and restricts sale or redistribution of the components themselves in their original form. The README calls it MIT, while the linked license adds the Commons Clause. Use the license file as the verified source and confirm the notice bundled with the pinned package before adoption. The documented setup adds `@animate-ui/react` and `motion` with the chosen Radix or Base UI primitive family and example styles that assume shadcn/Tailwind conventions. Reuse only the required client-side primitive and substitute RAFIQ styling, icons and focus states. Avoid introducing a second primitive family for a single control. [Source](https://github.com/imskyleen/animate-ui) · [License](https://github.com/imskyleen/animate-ui/blob/main/LICENSE.md) · [Installation and covered primitives](https://animate-ui.com/docs/cli)
- **M · Motion for React.** The linked public demos or docs show the technique and example source. The underlying `motion` package is free under MIT and requires retaining copyright and permission notices with distributed copies or substantial portions. The alternatives use the free APIs and pair them with RAFIQ’s own markup and icons. Next.js can use Motion within a client component, with one package and no shadcn CLI. Check route bundle impact if Motion is introduced. The control or live region owns accessibility semantics. Use reduced-motion hooks or explicit CSS where needed, since Motion’s global setting can leave opacity transitions running. [Source](https://github.com/motiondivision/motion) · [MIT license](https://github.com/motiondivision/motion/blob/main/LICENSE.md) · [Next.js setup](https://motion.dev/docs/react-installation) · [Bundle-size guidance](https://motion.dev/docs/react-reduce-bundle-size) · [Reduced-motion guidance](https://motion.dev/docs/react-accessibility)
- Both approaches fit the proposed React client portion of RAFIQ’s Next.js/TypeScript frontend. This is source-level compatibility. The approved screen design and frontend integration still need keyboard, screen reader, reflow and reduced-motion checks. In Pen.dev, recreate the RAFIQ-styled endpoints as native layers and annotate timing. Sliders, switches, option semantics, authorization and save announcements need working frontend controls. [Frontend architecture](../../TRD.md) · [Accessible control patterns](https://www.w3.org/WAI/ARIA/apg/patterns/)

## Recommended treatment and static choices

| Opportunity | Recommended behavior | Static choice |
| --- | --- | --- |
| Warning audio | Standard switch with a short CSS thumb move. C01 is the closest external primitive if the shared form already uses Animate UI with Radix. | Labeled switch with immediate position and On/Off state. |
| Before and after | Reuse the verified RAFIQ slider visual reference, keep the number and thumb responsive to input, and give the driver an exact non-drag adjustment. The range is short enough for a select if preferred. C03 or C04 adds value chiefly when the shared primitive is already adopted. | Two independent range inputs with precise non-drag access, or two standard selects listing 0 through 5 seconds. |
| Recording categories | Native checkbox group with an immediate tick and optional short surface emphasis. Keep only the active row’s visual treatment in motion. | Native checkbox group with steady checkmarks and visible focus. |
| Warning visibility | Two radio segments. A brief local surface transition can reinforce the selection. | Two static radio segments with a selected outline and a mark. |
| Clip explanation | Native disclosure with optional short chevron or reveal motion. Keep the essential recording limits readable even when closed. | Standard disclosure with instant open and close, or visible explanatory text if the approved layout has room. |
| Save feedback | Reuse D19’s stable inline status. Fade the decorative check briefly after confirmation. C11 is a fit if Motion is already available. | Inline text and an optional static check. |

The animated Toast was also reviewed. D20 needs local confirmation the driver can find beside Save and a separate effective consent status. A transient toast adds a second feedback location, so it is excluded from the proposed choices. [Animate UI Toast](https://animate-ui.com/docs/primitives/base-ui/toast)

Approve the recommended built-in motion, select the static version, or choose individual candidate IDs. The controls should remain usable if an animation is interrupted or disabled, and restoring a saved value should render its final state directly.
