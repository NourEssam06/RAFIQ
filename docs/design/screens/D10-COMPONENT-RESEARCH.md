# D10 Clips — layout and component proposal

This proposal records the alternatives considered for D10. The user approved the structured list and standard controls with a brief Back highlight on 25 November 2026. D10 is an Operate surface for the signed-in driver reviewing a completed session while stationary. The driver should be able to find the incident they remember, tell whether its clip can play and for how long, open it in D11, or delete that specific clip and continue reviewing the incident. [Approved Pen.dev handoff](D10-SHAPE.md) · [Screen requirements](../../SCREENS.md#d10-clips) · [Experience and retention](../../EXPERIENCE.md#review-analysis-and-data-lifecycle)

## Layout decision

Both layouts start with the existing private navigation, **Clips** selected, an H1, and labeled **Behavior**, **Capture date**, and **Session** controls. Keep active selections and **Clear filters** in view, then indicate **Newest captures first** and the displayed time zone. Rows or cards identify the same authorized behavior, incident time, source session, clip state, and expiry where applicable. Separate the incident time from the capture date used for filtering and ordering. **Open clip** is the primary row or card action when playback is available. Keep session and incident navigation available where those records are independently authorized. [D06 Sessions](D06-SHAPE.md) · [D08 Incident and alert details](D08-SHAPE.md) · [D11 Clip replay](../../SCREENS.md#d11-clip-replay)

| | A · Structured evidence list | B · Evidence media layout |
| --- | --- | --- |
| First viewport | Flat, aligned results. Behavior and incident time lead. Session, state and expiry line up across rows. **Open clip** and a visible actions button sit at the end. | Two columns of consistent evidence cards. A compact media slot groups duration, availability and **Open clip**, followed by behavior, incident time, source session and expiry. A text action area remains visible even without imagery. |
| Evidence review | Compare incidents, expiry and upload state without opening an item. Uses the D06 row rhythm and D08 evidence labels. | Each clip has a clearer visual boundary and larger replay target. The card reads like a short incident summary, borrowing D08’s grouping. The driver sees fewer items per viewport and must scan vertically for comparable fields. |
| Narrow width and zoom | Stack each row in the same reading order with field labels. Keep one page scroll and preserve focus and the row anchor. | Collapse to one column before metadata needs truncation. Keep the same metadata and order. Without consistent preview sources, the larger media regions use more space for the same evidence. |
| Media and privacy | Text-led rows require only authorized metadata. | Design with a neutral media slot and synthetic art only in Pen. A real still would require a separate authorized derivative contract with equivalent expiry, deletion, no-store and access checks. Both concepts defer video fetching to D11 on request. |

**Recommendation for approval — A.** Drivers search by known incident context and need to compare different availability and expiry states. A places those facts in consistent positions, fits more incidents at laptop widths, and follows the established Sessions pattern. B is viable if visual recognition later becomes a validated need. The current API describes private video replay and clip metadata. Thumbnails and preview delivery would need product and API approval. ## Search, navigation and deletion

- Use the three labeled filters as structured search across retained eligible data. Default to any behavior, capture date and session. The documented filter accepts one behavior and one owned session, plus capture-time bounds. Typing in a session picker, if needed, finds a session option within the authorized source. It does not search the clip result text. Confirm a complete, paginated owned-session lookup or labeled option set before choosing the picker behavior. For a local date range send inclusive start and exclusive next-day start in UTC. Show **Apply**, removable active selections, and **Clear filters**. Reset the cursor when applied scope changes. With cursor paging, use D06’s explicit navigation approach. An empty page or a page-size count must not be presented as the total library size. [D06 paging](D06-SHAPE.md) · [Clip query contract](../../API.md#7-detailed-endpoint--operation-specifications)
- Link the source session to D07. Provide **View incident** in the clip’s action menu when the D08 occurrence is authorized and resolvable. Show **Open clip** as a direct D11 link for currently playable recordings. Back restores the committed filter set, result segment, scroll and focused opener under the same verified owner. If the clip no longer plays, focus its current state or nearest surviving result, then the results heading if no result survives. [Returning to context](../../SCREENS.md#shared-design-rules)
- Label the overflow trigger with the specific clip’s behavior and incident time. Offer **View incident** and **Delete clip** when eligible. If deletion is the only available action, use a named text button. Confirmation names the clip and explains that replay and linked access end immediately, independent session and incident records remain, and dependent hosted reports are withdrawn where applicable. Focus **Cancel** first, show **Deleting…** during the request, and announce **Clip deleted** after confirmation. Move focus to the next surviving row or results heading. On recoverable failure keep the target and scope and offer retry. If a response is uncertain, reconcile against current authorized state before reporting an outcome. Deleting a queued item must also prevent its retry or eventual publication. Confirm queue-only deletion behavior before presenting it as an available action. [Lifecycle requirements](../../PRD.md#86-clip-and-report-lifecycle) · [Dialog behavior](../../SCREENS.md#shared-design-rules)

## States and evidence boundaries

| State | Design treatment |
| --- | --- |
| Initial load | Keep navigation, heading and filter controls stable. Show **Loading clips** once in a polite status and static, inaccessible-to-AT placeholders matching the results geometry. |
| Applying filters / paging | Mark the results region busy. Preserve keyboard focus and the filter choices. If old results stay visible, identify their prior scope until the new scope commits. Scope a paging failure to pagination and offer **Retry**. |
| No clips / first use | **No clips yet** only when first use is known. Explain that eligible recordings appear here when enabled. Link to **Monitoring settings** if helpful. If prior history is unknown, use **No clips available** with a route to **Sessions** for independent records. |
| No matches | **No clips match these filters** after a successful scoped lookup. Preserve the selections and offer **Clear filters**. |
| Offline or temporary failure | **Clips couldn’t load** with **Retry** when eligible. Show verified local queue information only for the current authorized browser context, clearly marking it as device-local and separate from unknown hosted results. An offline or failed fetch never reads as an empty library. |
| Queued / uploading / pending | **Queued** or **Uploading** comes from an authoritative device or transfer signal. Show determinate progress only when measured. Remote `pending` alone displays **Pending**. Show the queue deadline when known. Hosted clips use the actual hosted expiry once available. |
| Available / truncated | Pair the text state with a non-color cue, show exact expiry, and expose **Open clip**. Where applicable, label **Available first segment** and show recording duration separately from the incident duration. |
| Unavailable / expired / access lost | For returned authorized metadata, show **Unavailable** or **Expired** with a verified reason where supplied. In D08, explain recording declined, category excluded, expiry, or capture/upload limit only when the original authorized evidence supports it. Never reconstruct expired or deleted library entries from stale client data. For a protected link with lost authority, use the generic P08 treatment and clear private UI, focus targets and media references. |

Queued clips expire **24 hours from capture**, hosted clips **seven days from capture**, and independent session/incident metadata **90 days from session end**. Deletion and expiry immediately end access, with retained copies purged within **30 days**. Link to D22 **Privacy** for the full policy. The driver’s browser must drop private results and pending queue UI on account switch or sign-out. Keep private media out of application/browser caches, service-worker caches, third-party previews, and ambient fetches. Revalidate authorization on Back and when a clip becomes ineligible. [Retention and Privacy](../../SCREENS.md#d22-privacy) · [API caching and invalidation](../../API.md#10-pagination-filtering-sorting-and-caching)

## Motion, accessibility and Pen representation

- Proposed motion is one 150–180 ms opacity accent at the restored row on Back, matching D06 and D08. Commit scroll, focus and results immediately. Keep skeletons, results, status changes, empty states and deletion feedback still. If an animated filter or menu is approved, limit it to a short opacity transition. Reduced motion shows final states immediately. Render focus independently of any highlight. [D06 return treatment](D06-SHAPE.md) · [D08 selection treatment](D08-SHAPE.md)
- Use labeled controls, skip link, a real results heading, visible focus and status text plus non-color cues. For an aligned table retain column relationships at desktop and field names when stacked. For cards use an ordered list with named actions. Tab to the filter controls, each row’s available destinations and its actions. Use the menu’s normal arrow navigation and restore focus after dismissal. Announce results or verification once and announce deletion after confirmation. Test long labels, long expiry dates, 200% zoom, and 390 px and 320 CSS px reflow. [Shared design rules](../../SCREENS.md#shared-design-rules)
- After approval, plan editable Pen variants for desktop mixed states, narrow reflow, filter open and applied, first use, filtered empty, loading, recoverable failure, menu open, delete confirmation/pending/success, and Back restored or expired on return. Use synthetic evidence and show start/end frames for any approved transition. Browser implementation owns the actual data requests, private access, focus, announcements, and reduced-motion preference.

## Contract items for implementation

1. The `ClipPage` schema supplies clip IDs, session/incident IDs, capture and expiry times, media duration, truncation, pending/available/unavailable, and possible reason. Required behavior labels, incident timestamps and human-readable session references need authorized enrichment from the session and incident contracts, or a clip-list projection. Confirm a bounded lookup that avoids a request per row. Confirm where recording declined and category excluded can be read as historical incident facts. [API contract](../../API.md#7-detailed-endpoint--operation-specifications)
2. Specify how the encrypted local queue and hosted pending state reconcile by stable clip ID, including correct source-specific expiry, upload progress, consent withdrawal and deletion during transfer. A hydrated clip must not briefly appear twice or return after deletion. Confirm exact behavior when offline deletion cannot complete. [Offline data and upload design](../../TRD.md#2-session-recording-and-offline-contracts)
3. Acceptance includes a combined filter query spanning several pages, a single empty result, first use, filter retry, queued-to-uploading-to-available, expiry during review, deletion with surviving D08 incident, and a same-device account switch during a pending refresh. Verify zero private thumbnails or video-byte requests from the D10 results surface and no prior-account metadata after identity changes. [RAFIQ journeys](../../SCREENS.md#requirements-and-prototype-walkthroughs)

## Choices presented for approval

- **Layout** — A · Structured evidence list (recommended), or B · Evidence media layout using a neutral media slot.
- **Components and motion** — Standard set D10-C01/C04/C06/C08 with the brief Back accent (recommended), the same set with all motion off, or individual component IDs and scope for the motion they add. Layout B uses D10-C10 by default.
