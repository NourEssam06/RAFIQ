## Workspace behavior

1. **Select a source.** From Analysis, start with **Select an eligible session**. From D07, validate and preselect the authorized session, and preserve **Back to session** while that context remains accessible. Prefer date, start time, and displayed zone for identification, with the same date/time convention as D06. The selector lists only the driver’s eligible, retained, compatible sources. Use reachable cursor paging when needed. The MVP wire contract has no search parameter. Server-side eligibility includes the measurement series, compatible observations and timing, and sufficient observed data. Exclude clips and precise location from the form and replay. [D07](../../SCREENS.md#d07-session-detail) · [What-If API operations](../../API.md#7-detailed-endpoint--operation-specifications)
2. **Read what supports this replay.** Show the session date/time and zone, **Measurement version**, **Recorded policy version**, and **Reference labels** with explicit availability text. Show catalog and model versions under **Source details** when helpful. Keep required provenance and label status visible even if supplemental details collapse. For a confirmed unlabeled source, use “Reference labels unavailable. You can still compare recorded and simulated counts and rates. Accuracy, false alarms, and missed detections need reference labels.” Precision and recall are also gated on compatible reference labels in D13. A source-level positive flag does not establish coverage for every selected behavior. [D13 evidence rules](../../SCREENS.md#d13-what-if-result)
3. **Adjust supported thresholds.** Build one grouped row per returned adjustable behavior. The approved interaction is a bounded slider and exact-value field for the same detection score. Keep the controls synchronized for valid values, including keyboard actions, and keep draft text editable when it is incomplete or invalid. Clear a prior source’s threshold draft only after switching sources and explain that a new source has its own supported thresholds. Include a visible range, increment and unit or score label once approved. Preserve a fixed thumb hit target, allow track clicks and keyboard operation, and let the exact field cover every valid value. Keep digits and caret stable. Use an explicit included state if drivers can submit a subset of behavior overrides. Prepare a Pen sample with one included row and exact value `0.82`, and label it as synthetic. The draft API proposes `0–1` and a nonempty set of unique supported overrides. Range, increment, initial values, decimal handling and the meaning of omitted behaviors still need qualification. Keep the slider unavailable when its bounds, increment or initial position are unknown. Display a recorded baseline score only if it comes from the selected source’s approved policy data. [API schemas](../../API.md#7-detailed-endpoint--operation-specifications)
4. **Submit and open D13.** **Run simulation** submits one snapshot of the selected source and validated overrides. Keep context in place and show **Starting simulation…** alongside the action while awaiting durable acceptance. Suppress duplicate submission and route to D13 once the API returns the run ID. D13 owns the queued/processing state and the **Recorded baseline** / **Simulated result** comparison. A timeout with uncertain acceptance keeps the submitted snapshot and reuses its idempotency key when reconciling or resending the same submission. Keep the edited draft separate from prior runs and their original inputs. Returning from D13 restores the eligible D12 draft or saved-run row, scroll and focus according to entry. [D13 result](../../SCREENS.md#d13-what-if-result) · [API error handling](../../API.md#11-error-handling-standards)
5. **Reopen saved runs.** Show creation time and zone, source session, and text status. Use **View run** for eligible queued, processing or failed entries whose current job details can be opened, and **View result** for ready entries. Keep run creation time distinct from last status update. Use the API’s creation order and bounded **Older runs** pagination. Unavailable rows appear only when the API authorizes a safe summary. Otherwise clear affected data and apply the shared protected-item handling on stale direct links. Opening an eligible run navigates to its own D13 record. ## States and feedback

| State | D12 treatment |
| --- | --- |
| Checking access or initial loading | Keep the shell and historical scope visible. Use separate source and history placeholders. Say **Loading eligible sessions…** or **Loading saved runs…** as applicable. Reveal private details after authorization. |
| Ready, no selection | Keep the selector and saved runs usable. Show **Select a session to see its supported thresholds.** before the threshold area. |
| No eligible sources | Use **No eligible sessions** and “What-If needs a retained, compatible session with enough usable observations.” Offer **View sessions** (D06). Give an insufficient-observation reason for a particular session only if separately authorized and supplied. An empty source list can coexist with an authorized history. |
| No runs | **No saved runs yet.** Keep the configuration action available when inputs qualify. |
| Invalid input | Put exact range or increment errors beside the field, associate them programmatically, and focus an error summary with field links for a failed submit. Keep other valid inputs. Allow correction and an explicit resubmission. |
| Load, network or paging failure | Use a scoped retry for sources or saved runs. Preserve independently authorized results and valid draft entries while recovering. Distinguish a temporary failure or offline state from an empty list. |
| Selection unavailable, including expired or removed mid-edit | Clear its private facts and dependent controls once loss is known. Refresh eligible choices, focus the selector or fallback heading, and show **This session is unavailable. Choose another eligible session.** Use this generic message for a D07 preselection that fails revalidation. Apply P08 to an inaccessible protected resource link, with authorization checked before exposing any context. Clear private data on account change or sign-out. |
| Starting, queued, processing | Starting belongs beside the D12 form action. Queued and processing appear as distinct, still labels on eligible history rows and in D13. Use one polite announcement per meaningful change. Present the API’s job states as text and a non-color cue. |
| Ready, retryable or terminal run | A ready row links to D13. D13 handles same-input retry for a transient run failure once the retry contract is defined. D12 offers a source-selection recovery for invalid or expired input. Use a safe authorized state for an unavailable run, including after deletion or expiry. |

## Contracts to confirm before implementation

- `ReplaySource` supplies timestamp, versions, adjustable behavior codes and a Boolean `hasReferenceLabels`. It needs a qualified provider for the per-behavior bounds, step, default or recorded score and validation precision. Confirm subset semantics, basic display names from the versioned catalog, and label coverage detail required by D13. A source-level Boolean can communicate availability without claims about individual behaviors.
- D07 preselection needs an authorized source lookup that works beyond the current cursor page. Confirm reason mapping for compatibility, insufficient observations and expiry within authorized context, and what happens if access or eligibility changes mid-run.
- The proposed saved-run row needs an authorized source summary and immutable `createdAt` even when `result` is null. `Job.updatedAt` records a different event. Confirm the safe projection for withdrawn/expired runs, scoped reason mapping, and a same-input transient worker retry action. The draft What-If API exposes create, list and get. Resolve polling and retry limits through the API contract. ## Acceptance criteria

- Enter from Analysis and from an eligible D07 session. Verify preselection after authorization, clear lost or expired selections, and keep history independently navigable. Check unauthorized and switched-account cases with a late network response.
- Edit a valid threshold from both inputs and check that the two controls agree. Exercise exact endpoints, invalid precision, empty text, out-of-range values, unsupported and duplicate behavior codes, source changes, and keyboard-only use. Confirm no result is calculated during editing and no live-policy or session write is triggered by the run.
- Submit an unlabeled eligible source and reach one saved D13 comparison with label-dependent metrics withheld. Confirm immutable input scope and versions on reopen. Verify that retry after an ambiguous acceptance links to the same logical submission, and that queued/processing/readiness stays understandable with reduced motion and without a timer or progress estimate.
- Verify meaningful focus and status updates, visible labels, reflow at 320 CSS px and at 200% zoom, and legibility of long dates, version strings and localized decimals.
