# D02 component research

Source and license review, 25 November 2026. This comparison uses published demos, documentation, and source. Runtime behavior and device performance require frontend verification.

## Selected direction

The approved camera-first workspace uses the fixed status list (**D02-C01**), static preview guide (**D02-C04**), native consent controls (**D02-C07**), and RAFIQ’s compact arc (**D02-C10**). Declining clips completes the choice for this session and preserves the saved preference. Keep readiness rows in a fixed order with visible text and icons. Use one short status cue when RAFIQ observes a real transition. Show the compact arc beside the active verification, initialization, or account check. Each state must make sense in a still frame. [Approved D02 design brief](D02-SHAPE.md) · [D02 screen requirements](../../SCREENS.md#d02-start-session-and-readiness) · [RAFIQ loader](../../../Pen%20Design/RAFIQ-loader.md)

The driver completes readiness while stationary. Online account and network eligibility, camera permission and device availability, usable framing, file verification, initialization, and recording choice must reflect their own results. A driver who declines clips can start when the other applicable checks pass. An eligible supervised session has its own authorization and revocation controls. Cancel returns to the origin. These conditions determine availability of **Start monitoring**. Motion is presentation only. The browser owns the real camera permission prompt. In production, send a camera-only request after the driver selects the camera action. Render waiting, available, denied or policy blocked, missing, and temporarily unusable from the actual result. An ignored browser prompt can leave the request unresolved. Keep useful waiting instructions and avoid declaring a failure based on elapsed time. Tie framing feedback to RAFIQ’s usable-view result. On permission denial, missing hardware, or poor framing, provide a specific correction and **Recheck**. Show the supported setup for incompatible devices or browsers. Keep the preview local. A Pen prototype represents these states with mock images and copy. [Media Capture and Streams specification](https://www.w3.org/TR/mediacapture-streams/) · [getUserMedia permission, exceptions and pending behavior](https://www.w3.org/TR/mediacapture-streams/#dom-mediadevices-getusermedia) · [D02 screen requirements](../../SCREENS.md#d02-start-session-and-readiness)

Reject **Aceternity Webcam Pixel Grid** for D02. It transforms the feed into a real-time pixel effect and exposes motion-sensitive grid controls. RAFIQ needs an unobscured preview, an understandable guide, and ownership of the single camera lifecycle. The existing RAFIQ **Face scanner** loader risks making framing look like identity verification. Both are excessive for an overlay that can be drawn once. ## Integration and verification notes

- Use existing tokenized surfaces and status colors. Give every outcome a visible word or reason. For camera and setup status messages, use a mounted polite live region for meaningful changes. Keep focus on the user’s action during background state changes. Announce a failure once, with its recovery path. Avoid per-frame announcements and percentage chatter. [RAFIQ accessibility floor](../../EXPERIENCE.md) · [WAI status messages](https://www.w3.org/WAI/WCAG21/Understanding/status-messages) · [WAI progress announcements](https://www.w3.org/WAI/WCAG22/Techniques/aria/ARIA25)
- Keep live preview free of gradients moving across the frame, blur, filter transitions, scanning lines, and continuous ornamentation. Preserve camera readability, button position, and text placement throughout. Give reduced motion the same copy, control availability, and state timing as the standard presentation. Proposed timings in this draft are design choices, with native CSS as the baseline and any heavier motion implementation subject to measuring on the supported device. [RAFIQ experience constraints](../../EXPERIENCE.md) · [CSS reduced-motion support](https://drafts.csswg.org/mediaqueries-5/#prefers-reduced-motion)
- Verify normal operation, complete readiness after a decline, identical reduced-motion and still states, screen-reader announcements, visible focus, offline and unsupported environments, and each recoverable permission and setup branch in the supported desktop browser. Pen can show flow and state variants. Browser permission behavior, camera display, status announcements, and performance require implementation testing. [D02 requirements](../../SCREENS.md#d02-start-session-and-readiness) · [RAFIQ accessibility acceptance](../../EXPERIENCE.md)
- Keep copyright and license notices with substantial copies of MIT or ISC source. Review each individual source or asset. Motion’s library uses MIT and GSAP applies its own no-charge license. LottieFiles’ free public assets have separate redistribution terms, and Rive’s runtime license is separate from export terms. Spline has its own community remix license.
