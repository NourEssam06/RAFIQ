# D06 Sessions — shaping proposal and component research

Design exploration for the English-language private driver app. Impeccable mode: Operate. The selected direction is recorded in the [approved D06 handoff](D06-SHAPE.md).

## Job and visual reference

Find an owned past session by when it started, tell whether review is ready, and pick up in the same place after checking the session. Enter from **Sessions** in driver navigation, **Back to Sessions** in D05, or **View session history** in D19. The first-use action opens D02 readiness. In a populated history, the row link leads to ready review in D07 or to authorized status and recovery in D05. The history contains session metadata. Charts, evidence playback, and session deletion are handled in the review and privacy flows. [Screen rules and D06](../../SCREENS.md#d06-sessions) · [Experience component patterns](../../EXPERIENCE.md#component-patterns)

The current Pen document shows the D01 desktop and narrow private shell, flat dividers, a dense ordered event list, static placeholders, and inline unavailable feedback. Its Foundations board and D01 use Space Grotesk, the documented Mori substitute. Carry over the private navigation order, active pill, button roles, icons, and focus treatments. Use `colors.canvas` / `$canvas` (#0e100f), `colors.ink` / `$ink` (#fffce1), and `colors.accent-stone` for secondary copy. Start with `spacing.md` (16 px) for shared row and content spacing and `spacing.xl` (24 px) between groups. Use the existing neutral panels and dividers, with status color confined to small cues and paired with a word and icon. Only the navigation and verified matching controls should be reused as shared visual patterns. The D06 table or grouped list and its return marker need their own variants. ## Layout choices

### A · Aligned session table — recommended

Use D01’s full-width private shell. **Sessions** is the active destination. Below the heading, identify the ordering and the time zone in one quiet line, for example **Newest first · Cairo (UTC+02:00)** for a fixture where the offset is valid throughout. Use an unboxed, divided table with aligned time and duration fields, a review column wide enough for the occasional authorized reason, and a consistently positioned detail link. The return marker is an inset edge and a subtle background on the previously opened row. Keep the link’s visible focus ring distinct. At narrow desktop widths, wrap the metadata and reason. At high zoom or insufficient width, render a single stacked list with per-field labels and the same order, actions, and anchor. This fits the Dashboard’s flat data treatment and lets drivers scan review states and times across multiple runs.

```text
Sessions                                      [Start session]*
Newest first · Cairo (UTC+02:00)

Started                     Ended    Duration   Review status    Open
24 Nov 2026 · 09:42         09:54    12 min     Ready            View details
24 Nov 2026 · 09:01         09:08     7 min     Syncing          View status
                                               Interrupted
23 Nov 2026 · 16:20         16:40    20 min     Unavailable      View status
                                               No usable observations†

                         [Newer sessions]  [Older sessions]
```

### B · Date-grouped session list

Keep the same shell, heading and pager. Give each local calendar date a section heading and divide its entries with the Dashboard event-list rules. Put the local start time first in each item, end time and duration immediately below or beside it, and the same status and single link in a trailing cell on wide screens. Stack these facts in reading order at zoom. This has a natural narrow layout and makes repeated same-day starts easy to find. Date groups add vertical space and weaken cross-day column scanning. Repeat the date heading when the same day continues onto another page. The full start date stays in each link’s accessible name.

```text
Sessions                                      [Start session]*
Newest first · Cairo (UTC+02:00)

24 November 2026
  09:42 · Ended 09:54 · 12 min          Ready            View details
  09:01 · Ended 09:08 ·  7 min          Syncing          View status
                                       Interrupted
23 November 2026
  16:20 · Ended 16:40 · 20 min          Unavailable      View status
                                       No usable observations†

                         [Newer sessions]  [Older sessions]
```

\* Reuse the shell’s distinct Start action in populated history. In first use, place the primary Start action in the empty state with one prominent instance. \† Example cause only when an authorized source supplies it.

## Row content and routing

- Use local start date and time as the row identifier. Use one clearly named zone, with a row-level distinction when offsets vary and an end date when a session crosses midnight. Use an unambiguous written date for English fixtures and retain the underlying instants. Align the duration figures and use explicit units. Use **Duration** for elapsed wall-clock start-to-end time if that display definition is confirmed. The measured **Monitored time** in D07 has its own pause rules. Never substitute `lastDurableObservationMs` for either metric. If the end or duration cannot be established, use **End time unavailable** or **Duration unavailable** in the applicable field. [D07 metrics](../../SCREENS.md#d07-session-detail) · [Session wire schema](../../API.md#7-detailed-endpoint--operation-specifications)
- Treat **Ended** and **Interrupted** as lifecycle context and **Syncing**, **Processing**, **Ready**, and **Unavailable** as review outcomes. Show **Interrupted** as a second line when authorized and known, including alongside **Ready**. For an ordinarily ended row, **Ended** can appear in a secondary position when relevant, particularly in D05 routing and review-pending examples. Use human-readable text and a non-color cue. An unresolved job should never visually imply that review is ready.
- **View details** opens D07 once the required records and analytics are ready. **View status** opens the authorized D05 status view for ended sessions awaiting review, interrupted recovery, sync, processing, and authorized unavailable rows. Put an authorized known reason directly below **Unavailable** and let D05 explain and expose a retry or reconnect action when the underlying operation permits it. Optional pending or missing clips leave ready review available. A deleted, expired, or inaccessible session uses the generic P08 message when opened and is removed from history once its loss of eligibility is known. [D05](../../SCREENS.md#d05-end-status-and-interrupted-session-recovery) · [P08](../../SCREENS.md#p08-unavailable-link) · [TRD recovery and sync](../../TRD.md#2-session-recording-and-offline-contracts)
- One link per row, named with the timestamp for screen readers, for example **View status for 24 November 2026 at 09:01**. Let the link work with keyboard, browser history, and open-in-new-tab. A static row highlight marks the return point. Use ordinary table semantics or ordered list semantics, and skip grid keyboard behavior and selection widgets. [WAI Tables Tutorial](https://www.w3.org/WAI/tutorials/tables/) · [WAI Reflow](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html)

## Loading, paging, and recovery

| State | Presentation and next step |
|---|---|
| First load | Keep the shell and heading usable. Show **Loading sessions…** and a few static skeleton rows using the eventual structure and column widths. Hide skeletons from assistive technology and mark the result region busy. |
| First use | **No sessions yet.** “After you finish a session, its review status will appear here.” **Start session** opens readiness. Use this copy when first use is established. |
| Empty retained history | **No sessions to show.** Offer **Start session**. A successfully returned empty page alone cannot distinguish first use from a cleared or expired history. If filters are introduced, use **No matching sessions** with **Clear filters**. |
| Page available | Use **Newer sessions** and **Older sessions**, following the session list’s stable newest-first order. The API provides a forward cursor and proposes 25 sessions per page. Use the remembered request cursor for newer pages. Omit total pages, arbitrary page jumps, and invented totals. Disable the unavailable direction and omit the pager when there is only one page. |
| Page loading or refresh | Keep the current authorized page readable while requesting the next one. Indicate progress near the pager and prevent overlapping requests. Commit rows and the pager together. For explicit successful paging, move focus to the results heading, bring it into view without smooth scrolling, and announce the result succinctly. On background refresh, retain focus and anchor. |
| Temporary list error or offline | First-load example **Couldn’t load sessions.** Offer **Retry** when eligible and mention reconnecting when offline is known. After a paging failure, keep the current authorized page and show **Retry** at the pager. Retry the original request, then announce the result. A cursor the service will no longer accept gets **Reload sessions** to fetch the latest authorized page. |
| History or record access lost | Remove unauthorized content immediately and use the applicable access flow. For a specific session, show P08 and **Back to Sessions** once history itself is authorized. Permanently unavailable review on a still-visible owned record remains an inline state with its authorized reason. |

Use one polite status region for meaningful results such as **Older sessions loaded** or an in-context **Session ready to review**. Keep row updates quiet when they are unrelated to the driver’s current context. Limit announcements to real changes, keep focus visible, and verify the complete path at a laptop width, a narrower desktop, 200% zoom and 320 CSS px reflow. The compact variant keeps all facts, status reasons and navigation in one readable vertical flow. [RAFIQ interaction and accessibility](../../EXPERIENCE.md#accessibility-floor) · [WAI Status Messages](https://www.w3.org/WAI/WCAG22/Understanding/status-messages.html) · [GOV.UK Pagination](https://design-system.service.gov.uk/components/pagination/) · [Carbon Empty states](https://www.carbondesignsystem.com/building-blocks/core/patterns/empty-states)

## Returning from D05 or D07

1. On departure remember the current page and applied scope, originating session ID, row’s vertical offset relative to the viewport, and focused link. Use memory scoped to the authenticated history entry and driver. Keep review payloads out of persistent browser caches and storage.
2. On Browser Back or **Back to Sessions**, revalidate the current driver, requested page and row before revealing it. Once the list is in layout, restore the same row at its previous relative offset and return focus to its link without a second scroll. Use the row ID across reordering, new sessions, and table-to-list reflow. A direct D05 or D07 entry with no prior history context goes to latest Sessions. [Shared return rules](../../SCREENS.md#shared-design-rules) · [API paging and caching](../../API.md#10-pagination-filtering-sorting-and-caching)
3. If the row disappeared, remove it and focus the nearest surviving row from the restored page. If none survives, focus the results heading or first valid history view with a concise message, for example **That session is no longer available.** When the saved page cannot be recovered, use the latest authorized page. Clear restoration state on sign-out, account change, or eligibility loss. Exact restoration is for an intact same-driver history entry. A full reload that loses the entry uses the safe fallback.

## Handoff questions grounded in the product contract

- **API data.** `Session` exposes `active` / `syncing` / `ended` and analytics `pending` / `ready` / `unavailable`. Clarify the authoritative interrupted flag, the rule mapping pending analytics to **Processing**, the safe unavailable reason and recovery eligibility for an owned row, and how the past-history view handles an `active` record. It offers start and sometimes end timestamps, while the requested duration requires a confirmed elapsed-time definition or a supplied duration value. Confirm how, if at all, the same-driver device-local interrupted record is discoverable from history before hosted sync. Pen fixtures can illustrate each state as a proposal. [Session list API and paging](../../API.md#10-pagination-filtering-sorting-and-caching) · [M03 Session history](../../ARCHITECTURE.md)
- **Shared, standard, custom and optional pieces.** Reuse the RAFIQ private shell, typography, action styles, and D01 feedback styling. Use standard table/list semantics, links, buttons, and pagination. Design custom wide and stacked session rows, status/lifecycle treatment, busy/error variants, and the restored row marker. External motion components remain optional candidates.
- **Pen handoff after approval.** Draw the default mixed-state desktop, narrow/zoomed list, first use, initial loading, recoverable list failure, paging failure, authorized unavailable row, and Back restored with both row marker and visible focus. Use synthetic rows. Pen can depict endpoints, mock zoom and annotate focus and state changes. Live authorization, cursor behavior, history restoration, keyboard order, announcements and reduced motion require browser implementation and verification.
